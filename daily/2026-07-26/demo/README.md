# 岔口 Forkpoint

面向「可续跑 / 可分叉 agent 会话」（OpenComputer 式事件日志）的**时间旅行归因 + 纠偏分叉调试台**。

给一次跑了几十步、给出「看起来对但错」结论的 agent 会话，岔口自动**揪出决定错误结论的那 1 个折返步**，
并支持「从该步 fork 一条纠偏轨迹 + 确定性重放」，用 before/after **证明**「修这一步 → 结论翻转」。

> 这是 `product-opportunity-lab` 的每日纯前端静态 Demo（模拟体验 + 价值可视化），
> 灵感来自 2026-07-26 Product Hunt AI 雷达日报中 **OpenComputer**（开源可续跑 agent 运行时：
> 每会话一台 VM、事件日志可从任意 seq 续跑、支持 checkpoint 分叉回滚）等「开源自持 agent 基础设施」信号。

## 它解决什么问题

长链路自治 agent 常给出「看起来专业、其实错了」（plausible-but-wrong）的结论。人要逐步读几十步日志才可能发现哪步坏了，
且找到也不敢确定因果，改完更无法证明「真的变对」。OpenComputer 让「回到某步续跑/分叉」在工程上**可行**（马达），
但没人告诉你「**该回到哪一步、为什么是这步、回去修了结论真的变对**」——岔口就是这个**方向盘 + 证据**层。

## 演示场景（全部为 mock 数据）

一个数据分析 agent 被要求「判断改版后新用户 **D7 留存** 是否显著提升、是否全量上线」，跑了 9 步给出
「提升 +8pp，建议全量上线」——**其实错了**：它在第 5 步把 `retained`(D1 留存) 误当成了 `retained_d7`(D7)。
改版只提升了 D1（新鲜感效应），并未提升目标 D7。岔口把它揪出来，并证明修正后结论翻转为「不建议上线」。

## 三个页面

1. **会话回放 Replay**：任务目标 + 9 步时间线（正常/异常/折返/被污染 四色）+ 选中步的读写状态与不变量校验 + 「自动定位折返步」+ 最终结论条。
2. **岔口纠偏 Forkpoint**：选一步 fork（第 3 步 or 第 5 步）→ 下游确定性重放并重新着色 → 命中/未命中折返点提示 + before/after 关键数字 + 价值指标。
   - 在**非折返步**（第 3 步）fork：结论不变 → 证明工具**有判别力**，不是见异常就报警。
   - 在**折返步**（第 5 步）fork：结论翻转为正确 → 命中。
3. **归因台账 Ledger**：每步 × 目标不变量校验表（含「是否传导到结论」）+ 折返判定解释 + 与 OpenComputer 的分工说明。

## 本地运行

```bash
npm install
npm run dev      # 本地开发，默认 http://localhost:5173
npm run build    # 产物输出到 dist/
npm run preview  # 预览生产构建
```

- 技术栈：Vite + React + TypeScript。
- `vite.config.ts` 设 `base: './'`（相对路径），保证部署到任意 GitHub Pages 子目录都能正确加载资源。

## 核心逻辑（可复算）

- `src/data/session.ts`：mock 会话事件日志（9 步）、汇总统计（D1 vs D7）、目标不变量与默认（含缺陷）决策。
- `src/logic/engine.ts`：确定性引擎。给定每步决策（指标列 / 清洗规则）复算逐步状态、不变量违反、最终结论；
  **折返步 = 最早「被违反、且单独修正它就能让最终结论翻转为正确」的步**（`applyFork` 用确定性重放证明因果）。
- 一个引擎驱动全部三个视图。

## 明确不做
