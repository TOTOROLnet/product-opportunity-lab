## 2. 候选机会（至少 3 个，均为创新切入点而非照抄）

### 候选 A：忆证 Yìzhèng — Agent 记忆的「回忆信任闸」（recall-time trust gate + 矛盾对账台）

- **创新切入点**：不做记忆的**存储**（与 Liminal/向量库/ChatGPT memory 解耦，坐在它们之上），做记忆的**使用时信任判定**。在 agent 准备**用某条记忆去动手**的那一刻，对每条被 recall 的记忆算并展示：来源（哪次对话/工具/文档、何时）、被独立 confirm 的次数、时效/衰减（区分"耐久事实"与"易变事实"）、是否与更新的记忆**矛盾**，综合成一个 trust score；低于阈值 → gate 拦下改为向人复核或降级，而不是"静默照做"。配一个**对账台**：合并重复、退役过期、解决矛盾、pin 住耐久真相。
- **目标用户 / 场景**：给 agent 接了持久记忆 + 真实读写权的团队（客服/运营/内部自动化），以及记忆平台方（想在存储之上加信任层）。场景：ops agent 依据"该客户是 VIP、一律退款"这条**8 个月前、已被上周新政策推翻**的记忆，准备自动退 $500。
- **五维评分**：痛点 4/5，机制新意 4/5，AI 核心度 5/5，一天可行性 5/5，启发价值 4/5 → 合计 **22/25**

### 候选 B：规程哨兵 — 对「agent 自写 SOP / 自建工具」做可审 diff + 回滚（源自 Conduit Operator）

- **创新切入点**：agent 每次自沉淀/修改 SOP 或自建工具时，呈现为可审 diff（改了什么、为何改、什么交互触发、此改动新放开了哪些真实动作权限），可回滚。
- **目标用户 / 场景**：跑"自改进垂直 agent"的运营团队。
- **五维评分**：痛点 3/5，机制新意 2/5，AI 核心度 4/5，一天可行性 4/5，启发价值 3/5 → 合计 **16/25**
- **我为何不选**：机制上与本实验室近期做过的 07-24 榫卯（工件契约 + 漂移哨兵）、07-27 合流（批量变更 dry-run + 碰撞）高度同源，对本实验室是**换皮重做**，启发增量低；且"diff 审批"这一形态今日报告里 Pinery 也在用，不够锋利。

### 候选 C：声音漂移仪 — 全篇「这还是不是你」的作者声纹热力图（源自 Pinery，但反其形态）

- **创新切入点**：不做 Pinery 那种**逐处** diff 审批（报告已判该赛道拥挤），而是反过来做**文档级/项目级**的"声音漂移"度量：一篇稿子从头到尾，哪些段落"还像你"、哪些已被抹成"通用 AI 腔"，给热力图 + 跨修订版的漂移时间线，回答"这篇里还有多少是我"。
- **目标用户 / 场景**：长期用 AI 辅助写作、又怕文风被磨平的作者。

## 3. 最终选择

- 选中：**候选 A — 忆证 Yìzhèng（Agent 记忆的回忆信任闸 + 矛盾对账台）**，总分 **22/25**
- 为什么选它（相对其他候选的优势）：

  3. **纯前端可诚实演示**：抽象/基础设施类，用"模拟体验 + before/after 价值可视化"就能让人 3 分钟看懂——不需要真实记忆库。

## 4. 深入论证（针对选中机会）

1. **目标用户**：① 给 agent 上了持久记忆 + 真实读写权（退款/改单/发消息）的团队；② 记忆/agent 平台方（Liminal、托管 memory、向量库厂商）想在"存储"之上补"信任"。
2. **核心痛点（真实、高频、可付费）**：随着 agent 记忆越攒越多且拿到真实动作权，它会**静默地基于过期 / 被推翻 / 只被说过一次 / 相互矛盾的记忆去动手**。一次错误退款、一次按旧偏好联系客户，代价是真金白银与信任。这是"记忆越多越危险"的结构性问题，而非一次性 bug。
3. **现有产品为什么没解决好**：
   - Liminal/向量库/ChatGPT memory 优化的是**写入与召回**，不回答"此刻该不该信"；
   - FlowTask 的门是**写入准入**（什么能进记忆），管不了记忆**进去之后过期/矛盾**；
   - Prefactor 评的是 **agent 的产出/动作**，看不到动作**背后依据的记忆**是否可信；
   - RAG 里的 rerank/相似度只回答"相关不相关"，不回答"新不新、真不真、有没有被更新的信息推翻"。
4. **为什么适合做轻量 Demo**：它的价值在"把不可见的记忆信任显性化"，天然是**可视化 + 模拟体验**题材。用一个"agent 动手前"的场景 + 一批带丰富 provenance 的 mock 记忆 + 一个透明可解释的 trust 公式，就能做出强烈的 before/after 对比，无需任何真实后端。

## 5. 不照抄声明（四项必填）

1. **创新切入点是什么**：一个与存储解耦的 **recall-time 记忆信任闸**：在 agent 用记忆动手前，对每条记忆做「来源 × confirm 次数 × 时效衰减 × 矛盾检测」的透明打分，低于阈值就拦下改为复核；并提供**矛盾对账台**（合并/退役/pin/解决矛盾）做记忆的持续"对账与遗忘"。
2. **解决的具体问题 / 场景**：agent 基于**过期/被新政策推翻/单次未确认/自相矛盾**的记忆**静默执行真实动作**（如按已作废的"VIP 一律退款"记忆自动退 $500，违反上周新政策）。
3. **相对被参考产品的增量价值（差异点）**：
   - vs **Liminal**：Liminal 是"用户自持的记忆**存储**"；忆证不存记忆，是坐在其上的**信任/对账层**，回答"现在该不该信这条"——可作用于 Liminal、ChatGPT memory、向量库之上（存储无关）。
   - vs **FlowTask**：FlowTask 是**写入门**（什么能进记忆）；忆证是**读取/使用门**（记忆过期/矛盾了还能不能拿来动手），并做写入门覆盖不到的**跨时间矛盾对账**。
   - vs **Prefactor**：Prefactor 拦的是 agent 的**产出/动作（行为）**；忆证拦的是 agent 依据的**记忆/信念（输入）**——对象不同、位置更上游，二者互补而非替代。
4. **为什么这不是照抄 X（本质区别）**：被参考产品的战场是"记忆的**拥有与写入**"和"产出的**运行时评估**"；忆证开辟的是"记忆的**使用时信任与时间对账**"这一独立层。一个动作可以通过所有 output eval、记忆也确由用户拥有，却仍因**依据了一条过期/矛盾的记忆**而错——这正是被参考产品结构上看不见、忆证专门盯的缝。它不是任何一款的克隆，甚至可与它们叠加使用。

## 6. 不确定性与风险

- **需求侧风险**：偏"前瞻性基础设施"——当下多数团队的 agent 记忆量还不够大、真实写权还不够多，痛感尚未普遍爆发；可能"对，但还早"。缓解：先绑定已经给 agent 真实动作权的高危场景（退款/发消息/改单）做楔子。
- **落地 / 技术风险**：真实系统里"矛盾检测"与"时效衰减模型"要做准很难（语义矛盾、领域相关的衰减速率）；trust score 若不可解释，用户不会信任这个"信任层"本身。缓解：公式透明可审、支持人工覆盖与 pin。
- **我可能判断错的地方**：① recall-time 信任也许会被大模型的长上下文 + 更强的自我一致性"内化"掉，不需要独立层；② 也可能它更应是记忆平台的一个内建特性而非独立产品（若如此，忆证的路线是做成可嵌入 SDK/中间件而非终端应用）。
- **本 Demo 的诚实边界**：Demo 用**确定性 mock 公式**演示信任判定，不含真实 NLP 矛盾检测/真实衰减学习；它证明的是"这个信任层长什么样、价值在哪"，不是"我们已实现工业级矛盾检测"。
