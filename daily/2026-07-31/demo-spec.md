# Demo 设计说明 — 2026-07-31

## 1. Demo 名称
**忆证 Yìzhèng — Agent 记忆的回忆信任闸（Recall Trust Gate）**

## 2. 一句话定位
在 Agent 用某条记忆去动手之前，先给这条记忆验明「来源 × confirm 次数 × 时效 × 矛盾」，低于信任阈值就拦下来复核，而不是静默照做。

## 3. 目标用户
- 给 agent 接了持久记忆 + 真实动作权（退款/改单/发消息）的客服/运营/内部自动化团队；
- 记忆 / agent 平台方（想在"存储"之上补一层"信任与对账"）。

## 4. 使用场景
一个酒店/民宿运营 agent（呼应报告里的 Conduit）正在处理住客 Charlie 的退款争议，准备**自动退款 $500**——它依据的是记忆里"Charlie 是 VIP，争议一律退款至 $1000"。但这条记忆是 8 个月前一次对话里说的、只被确认过 1 次，而**上周刚更新的政策**记忆明确写着"$200 以上争议退款一律需经理审批（VIP 不例外）"。没有忆证：agent 静默照做、违规退款；有忆证：gate 识别过期 + 矛盾，拦下改为经理复核。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 抽象 / CLI / API / 基础设施类产品（记忆信任是"看不见的中间层"）
- 采用的演示方式：纯前端「**模拟体验 + 价值可视化**」——
  - **模拟"动手前"的信任闸**（脚本化重放一个真实动作被拦下的核心工作流）；
  - **before / after 对比**（无忆证 = 静默错误执行 vs 有忆证 = 拦下并复核），直观展示增量价值；
  - **可交互对账台**（改动记忆状态 → trust score 与 gate 结论实时联动）；
  - **溯源/结构视图**（把"为什么信这条记忆"这一抽象判断可视化）。
- 演示的是**我们分析出的创新切入点（recall-time 记忆信任 + 矛盾对账）**，不是 Liminal（存储）/FlowTask（写入门）/Prefactor（产出评估）的克隆。

## 6. 核心流程
（用户从进入到"看懂价值"的主路径，3 分钟内可完成）
1. 进入 **① 动手前 · 信任闸**：看到 agent 准备执行的动作卡（自动退款 $500）与它依据的一组"记忆证据卡"，每张卡有 trust score 徽标（过期 / 单一来源 / 冲突）；顶部 gate 结论显示 **HOLD · 需人工复核**，并给出一句人话理由。
2. 点 **Before / After 开关**：左「无忆证」= agent 静默退款、事后才发现违反新政策；右「有忆证」= gate 拦下、把冲突与过期摊开、转经理复核。价值一眼可见。
3. 切到 **② 记忆账本 · 对账台**：在表格里对那条过期 VIP 记忆做"退役"或对矛盾做"以新政策为准"，或对某条耐久事实"pin"，**实时**看到 trust 分数变化，并看到顶部横幅提示"本次动作的 gate 结论已更新"。
4. 切到 **③ 溯源 · 信任拆解**：点任一记忆，看它被提及/确认/推翻的时间线（mock 对话/工具/文档片段）、按"易变/耐久"类别的衰减曲线、以及 trust 公式各因子的贡献拆解——回答"agent 为什么信它、为什么分数是这个数"。

## 7. 页面结构（<= 3 个主要页面，单页应用内 Tab 切换）
- **页面 1 · 动手前 · 信任闸（Pre-Action Gate）**：动作卡 + 证据卡列表 + gate 结论 + Before/After 对比开关。
- **页面 2 · 记忆账本 · 对账台（Memory Ledger）**：全部记忆表格 + 过滤（全部/过期/冲突/低信任/已 pin）+ 操作（退役/以新为准/pin/再确认）+ 实时联动。
- **页面 3 · 溯源 · 信任拆解（Provenance）**：单条记忆的证据时间线 + 衰减曲线 + trust 公式因子拆解。

## 8. 关键交互
- **Trust score 徽标**：每条记忆一个 0–100 分与色带（绿/黄/红），点开显示因子。
- **Before/After 开关**：切换"无忆证/有忆证"两种世界的结局。
- **对账动作**：退役、以新政策为准（矛盾的旧记忆自动降权/退役）、pin（耐久化、停止衰减）、再确认（+confirm、刷新时效）——均**即时重算** trust 与 gate 结论。
- **联动反馈**：账本里的改动，回写页面 1 的 gate 结论（例如把矛盾解决后，某张证据卡从红转绿）。

## 9. 使用的 mock 数据
（说明数据来源与结构，全部为 mock，不接真实后端/外部 API）
- `memories`：约 9–10 条记忆，字段：`id, statement, category(易变/耐久), sources[](type: chat|tool|doc, excerpt, at), confirmations, lastConfirmedAt, conflictsWith[], pinned, retired`。
- `scenario`：一个"pending action"（自动退款 $500）与它 recall 的记忆 id 列表、动作的政策约束。
- **trust 公式（确定性、可解释，纯前端计算）**：
  `trust = base × freshness(age, category) × confirmation(log2(1+n)) × sourceAuthority × (1 − conflictPenalty)`，
  阈值 0.6；`freshness` 对"易变"类记忆衰减快、"耐久"类几乎不衰减；`conflictPenalty` 由未解决的矛盾条数决定。
- 所有对话/工具/文档片段均为**虚构 mock 文本**，不涉及任何真实用户/密钥/外部 API。

## 10. 明确不做什么
- 不做登录 / 用户系统
- 不接数据库 / 支付 / 外部私钥 / 真实 API / 真实 LLM 调用
- 不做生产级后端；不做真实的语义矛盾检测（用 mock 关系）
- 不做真实记忆库读写（与存储解耦，仅演示"信任层"形态）

## 11. 成功体验标准
- 用户 3 分钟内能说出："它解决**记忆过期/矛盾时被 agent 静默拿来动手**的问题；用**动手前的信任闸 + 对账台**这么用；增量在于它是**存储无关的 recall-time 信任层**，Liminal/FlowTask/Prefactor 都没盯这条缝。"
- Before/After 对比能让人直观感到"没有这层会真的赔钱/丢信任"。
- 在账本里操作一次，能看到 gate 结论实时变化——证明这不是静态海报而是有逻辑的模拟体验。
