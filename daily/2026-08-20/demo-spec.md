# Demo 设计说明 — 2026-08-20

## 1. Demo 名称

对味 Duìwèi — 让 coding agent 的「选型」对你的口味（Taste-Calibrated Dependency Selection）

## 2. 一句话定位

把 coding agent 在一次 PR 里悄悄做完的依赖 / 库 / 工具选型决定变可读，从你的几次判断里学出可复用的「选型口味档案」，再回放去改判——看它省下多少体积、避免哪些后悔。

## 3. 目标用户

用 coding agent（Cursor / Claude Code / Origin Cloud Agent）高频产出代码的工程团队 / 技术负责人，尤其重视供应链、体积、许可、可维护性的中后台 / SaaS 团队。

## 4. 使用场景

agent 提交了一个 PR，为完成任务自主装了一批依赖。技术负责人想在合并前弄清：这些选型合不合我们的规矩？该换成什么？——但没有工具把 agent 的选择过程摊开、也没法把团队品味一次教会、复用到未来每次 agent 运行。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 可视化/交互类产品（交互为主）＋ 抽象能力的「模拟体验 + 价值可视化」
- 采用的演示方式：
  - 直接可点击交互：展开每个选型决定看替代对比；点选校准理由实时学口味；before/after 对照实时随口味变化。
  - 因为真实产品依赖 agent rationale + 实时 registry，这里用**确定性可解释的模拟选型引擎 + 全 mock 数据**呈现价值，并在 UI 里公开完整评分公式（透明、不黑箱）。
- 演示的是**我们分析出的创新切入点**（买方侧的选型决策透明 + 口味校准），不是 Gauge（卖方 GTM）/ Snyk-Socket（产物扫描）/ Dependabot（版本升级）的克隆。

## 6. 核心流程（3 分钟内可完成）

1. 进入「① 选型说明书」：看到 agent 这次 PR 悄悄做了 6 个选型决定，顶部实时汇总「几处会后悔 / 可优化 / 选得对味」；展开任一决定看 agent 理由 + 资深工程师挑刺点 + 替代方案逐轴对比表。
2. 去「② 口味校准」：点几下校准用例里的「挑刺理由」（如「太重了」「能用原生」「AGPL 用不了」），实时看到一份「选型口味档案」被学出来；也可用预设起步或手动微调权重。
3. 回「③ 对味重选」：看 before/after——哪些选型翻盘（agent 选 → 对味选）、避免了哪些后悔、省下多少体积 / 传递依赖 / 清掉几个许可硬伤，并核对完整评分公式。

## 7. 页面结构（<= 3 个主要页面）

- 页面 1「选型说明书」：PR 元信息 + 实时汇总条 + 6 个可展开的选型决定（替代对比表 + 挑刺点 / 好评）。
- 页面 2「口味校准」：预设口味按钮 + 校准用例（理由 chip）+ 学到的口味档案 + 手动权重（0–3）面板。
- 页面 3「对味重选」：省下 / 避免 汇总条 + 逐决定 before/after 卡片（翻盘理由 / 保留说明）+ 完整评分公式 + 不照抄声明。

## 8. 关键交互

- 展开 / 折叠选型决定；替代方案表高亮「agent 选」与「对味选」，标注 copyleft / 原生 / 体积过重 / 维护存疑。
- 校准理由 chip 多选 → 确定性映射到偏好权重（`learnTaste`）→ 全局口味实时更新，三个页面联动。
- 预设 / 手动权重按钮直接设定口味（转入手动模式，与 chip 解耦，避免互相打架）。
- 「全部关闭」口味时，引擎**只在候选严格优于 agent 选择时才改判**，并列一律尊重 agent 原选择——演示「不无谓翻案」。

## 9. 使用的 mock 数据

- `src/data/pr.ts`：一次真实感的 agent PR（通知服务：邮件 + 定时摘要 + 本地化时间 + 补零 + webhook POST + 模板渲染），含 6 个选型决定，每个决定带 agent 选中项 + 2–3 个替代，逐轴指标（体积 KB / 周下载 / 距上次发版月数 / 传递依赖 / 许可 / 是否一等类型 / 是否原生方案）——全部为演示用 mock。
- `src/data/calibration.ts`：4 个校准用例（另外几次 agent 选型的小例子）+ 每例的挑刺理由 chip（映射到 6 条偏好）。
- `src/engine.ts`：确定性纯函数——评分 `scoreCandidate`、改判 `tastePick`（仅严格更优才改判）、汇总 `summarize`、从例子学口味 `learnTaste`。
- 数据经 `_verify.ts`（一次性 esbuild→node 校验，已删除）核对：均衡口味下 4 处改判（3 后悔含 1 许可硬伤 + 1 可优化）、2 处保留，省 99KB、少拖 12 个传递依赖、整包移除 3、清 1 个许可硬伤。

## 10. 明确不做什么

- 不做登录 / 用户系统
- 不接数据库 / 支付 / 外部私钥 / 真实 registry / LLM / agent 运行时 / 外部 API
- 不做生产级后端
- 不做运行时拦截 / 审批门（刻意避开 gate 形态）；不扫 CVE（那是 Snyk/Socket 的活）

## 11. 成功体验标准

- 用户 3 分钟内能说出「它解决什么问题、怎么用、增量在哪」：agent 替我选型无人复核 → 学出我的口味 → 一键回放改判并看到省下的体积 / 避免的后悔。
- 首屏即讲清价值：「这次 PR 里 agent 悄悄做了 6 个选型决定，其中 3 个你八成会后悔」。
- 口味改动三页联动、评分公式公开可核对，让人相信这不是黑箱、也不是又一个 gate。
