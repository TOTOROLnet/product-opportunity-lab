# 众读 Zhòngdú — 发送前的「读者接收预演台」

> product-opportunity-lab · 2026-08-11 每日机会 Demo
> 纯前端静态原型（Vite + React + TypeScript），全部数据为 mock，不接后端 / LLM / 数据库 / 登录 / 支付 / 外部 API。

## 这是什么

把你只发一次、发错就亏的一段文字（冷启邮件 / 求职信 / 一句话融资），先交给**一屋子各不相同的 AI 读者**逐字读一遍：

- **围读台**：每位读者逐句读你的文字，注意力条实时起伏，内心反应逐条冒出，回放结束定位「目标读者在第几句流失」。
- **接收热力图**：同一段文字叠加词/句级热力（投入 / 走神 / 困惑 / 反感 / 流失），点句子看是谁、因为什么卡住；给出接收分 + Top 摩擦点，**只诊断不代写**。
- **改前改后**：勾选几种「改法」（换切入角度 / 把价值前置 / 给具体下一步），实时看到接收分与流失点如何变化——加分靠的是**结构与价值**，不是把句子改通顺。

核心切入点：把雷达 2026-08-11「AI Group Call（多 AI 实时辩论）」这一原语**反转**为**接收模拟**——不是让 AI 替你辩论一个目标，而是模拟你的真实读者替你预读你写好的文字，告诉你「哪一句、被谁、因为什么」流失。

## 与相关产品的区别（非照抄）

- **不是 AI Group Call**：它是围绕「一个目标」的多 AI 语音辩论（表演）；众读是围绕「你的具体文字」的多读者接收诊断（工具），产出是可定位到词的热力图与流失点。
- **不是写作助手（Grammarly / AI 改写）**：它们修语法/语气、直接给你改后文本；众读不改写，只告诉你特定读者在哪一句、因为什么流失/反感。

## 本地运行

```bash
npm install      # 安装依赖
npm run dev      # 本地开发（默认 http://localhost:5173 ）
npm run build    # 生产构建，产物在 dist/
npm run preview  # 预览已构建产物
```

## 目录结构

```
src/
  types.ts               # 类型定义
  logic/engine.ts        # 确定性接收引擎（纯函数：轨迹/热力/流失点/摩擦/接收分）
  data/readers.ts        # 读者画像池（mock）
  data/samples.ts        # 3 段样本文字 + 脚本化读者反应 + 改法（mock）
  components/
    ConfigBar.tsx        # 选样本 + 选目标读者
    ReadingRoom.tsx      # ① 围读台（逐句回放）
    HeatmapTab.tsx       # ② 接收热力图 + 诊断
    BeforeAfterTab.tsx   # ③ 改前改后
    shared.tsx           # 徽章 / 注意力条等小组件
  App.tsx                # 页面骨架与状态
```

## 说明与边界

- `vite.config.ts` 设 `base: './'`，保证部署到 GitHub Pages 的 `/<date>/` 子目录也能正确加载资源。
- 「读者反应」是**离线预计算的脚本**（在 `data/samples.ts` 里逐条声明），用于让接收模拟的价值在无网络、无密钥的情况下可体验；真实产品中，这些反应由 **persona 条件化的 LLM 在线生成**。
- 引擎数值已用一次性脚本核对（改前分低 / 目标早流失，改后分高 / 读到底），无随机、可复现。
