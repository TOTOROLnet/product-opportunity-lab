# Demo 设计说明 — 2026-08-22

## 1. Demo 名称
绕行 Ràoxíng — 模型路由「回退税」诊断台

## 2. 一句话定位
看见「便宜模型优先 + 自动 fallback」网关里那些**看不见的绕行**：把回退税（双付 + 尾延迟）与静默质量债从「省钱数字」里拆出来，并给按类别的改道建议。

## 3. 目标用户
接了 Router / OpenRouter / 自建 LLM 网关、正靠「便宜模型 + fallback」省钱的 AI 平台 / 基础设施 / 工程团队负责人。

## 4. 使用场景
运营者盯着一个「省了 67%」的成本仪表盘，想知道：这个数字有多少水分？哪几类请求在系统性回退/静默降级？改哪几条路由规则能把隐藏税换成诚实、可靠的节省？

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 抽象 / CLI / API / 基础设施类产品（LLM 网关内部行为）
- 采用的演示方式：纯前端**「模拟体验 + 价值可视化」**——
  - **模拟流量回放**：一份 mock 的网关请求日志（50 条 / 6 类请求）在确定性引擎上「回放」路由结果（便宜成功 / 回退 / 静默降级）。
  - **失败特征聚类（本 Demo 的核心新意基因）**：把回退与降级请求按失败特征聚成簇（输出截断 / 工具 JSON 格式错 / 逻辑边界错·静默 / 语气串味·静默 …）。
  - **before/after 对比**：三方对照（全走大模型 / 便宜优先+回退 / 绕行改道后）+ 「账面省 vs 真实省」诚实记账。
- 演示的是**我们分析出的创新切入点**（网关的诊断/归因层 + 诚实记账），不是 Router/OpenRouter 的克隆。

## 6. 核心流程
（用户从进入到"看懂价值"的主路径，3 分钟内可完成）
1. 进入 **① 回退地图**：顶部一个反直觉的诚实大标题「账面省 67% · 其中约 19% 是幻觉」；下面把 50 条流量按失败特征聚成几个簇，每个簇卡片显示：失败特征名、命中请求数、隐藏代价（回退次数 / 尾延迟秒数 / 静默降级数），静默降级簇被特别标红（「仪表盘算它省钱，其实输出已悄悄变差」）。点开簇看示例请求行。
2. 切到 **② 改道方案**：每个「系统性失败」的簇给出一条改道规则（如「工具调用 JSON → 直接走大模型，跳过便宜模型」）带开关；勾选后实时重算：回退避免数、回收的尾延迟、质量债 6→N、改道后的诚实成本。内置「别矫枉过正」守卫——对真正省钱的健康簇（短问答 / 结构化抽取）默认不改道，若强行改道会显示「钱↑、可靠性≈无收益」以自证。
3. 切到 **③ 对照 & 说明**：三方对照条（全大模型 / 便宜+回退 / 绕行后）；一个深色框展示**全部计算公式**（回退税、静默质量债、幻觉占比、诚实节省如何算），透明可复核；底部「非照抄声明」（vs Router / vs 可观测性 / vs 换挡）。

## 7. 页面结构（<= 3 个主要页面）
- 页面 1（Tab ①）：**回退地图**（诊断）——失败特征聚类 + 账面 vs 真实的诚实大标题。
- 页面 2（Tab ②）：**改道方案**（交互）——按簇改道开关 + 实时重算 + 「别矫枉过正」守卫。
- 页面 3（Tab ③）：**对照 & 说明**——三方对照条 + 透明公式框 + 非照抄声明。

## 8. 关键交互
- Tab ② 的改道开关：切换任一簇的「改道到大模型 / 保持便宜」，Tab ①/③ 的数字实时联动（跨 Tab 响应式）。
- 「别矫枉过正」自证：手动给健康簇（短问答）打开改道，会看到成本上升而可靠性几乎无变化，用交互证明「不是越改道越好」。
- 一键预设：「推荐改道方案」（只改系统性失败的 3 簇）/「全部改道（矫枉过正）」/「全部保持便宜（现状）」三个预设按钮。

## 9. 使用的 mock 数据
（说明数据来源与结构，全部为 mock，不接真实后端/外部 API）
- `data/traffic.ts`：6 类请求（短问答 / 结构化抽取 / 长文摘要 / 工具调用JSON / 代码补全 / 多轮客服），共 50 条；每类含 volume、便宜成功数 ok、回退数 fallback、静默降级数 degrade、失败特征 signature、少量示例请求文本。
- 成本/延迟模型（mock 常量）：便宜模型 $0.002/req、0.8s；大模型 $0.030/req、2.5s；回退 = 便宜(失败) + 大模型 = $0.032 / 3.3s。
- `engine.ts`：确定性纯函数——总账（全大模型基线、便宜优先实际成本）、账面节省、幻觉占比（回退浪费 + 静默降级的幻影节省）、失败特征聚类、按改道开关重算诚实成本/延迟/质量债、「只对严格更优的类别改道」守卫。所有引擎数字先用一次性 `_verify.ts`（esbuild→node）核对再进 UI，核对后删除。

## 10. 明确不做什么
- 不做登录 / 用户系统
- 不接数据库 / 支付 / 外部私钥 / 真实 API / 真实 LLM / 真实网关日志
- 不路由任何真实流量、不调用任何模型
- 不做生产级后端
- 不假装能自动判定「质量是否降级」——Demo 用 mock 语料并诚实标注「模拟」，且在文案里讲清真实版最难的环节（如何判定静默降级）。

## 11. 成功体验标准
- 用户 3 分钟内能说出：它解决什么（把路由省钱数字里的水分和隐藏税看清）、怎么用（看聚类 → 勾改道 → 看诚实对照）、增量在哪（诊断/归因/诚实记账，而非又一个路由网关或省钱计算器）。
- 首屏那句「账面省 67% · 其中约 19% 是幻觉」能立刻制造认知冲突并让人想往下看。
- 交互能自证「别矫枉过正」：不是改道越多越好。
