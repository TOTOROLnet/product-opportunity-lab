# Demo 设计说明 — 2026-08-25

## 1. Demo 名称

现成 Xiànchéng —— 跨 agent「已验证做法」检索与复用层（Demo）

## 2. 一句话定位

让你 agent 舰队里的每台"电脑"不再从零摸索：新任务开工前先"找现成的"——检索兄弟 agent 是否已在相似意图 + 相似
环境下成功做过，并把那次真实运行**蒸馏成一条已验证、去噪、去弯路的最短动作配方**直接复用。

## 3. 目标用户

跑 3~50 台自治 agent（每台有自己持久计算环境，如 Construct / Epho / 自建 VPS）的 solo founder 与小团队；
对"同一件事被 N 台 agent 各自重学、重复烧 token/机时"最敏感的人。

## 4. 使用场景

来了一个新任务（"把这个 Next.js 项目部署到 Cloudflare 边缘" / "修好这条 flaky Playwright 用例" /
"接上 Stripe webhook 沙箱"）。过去每台 agent 从零摸索、各自踩坑、各自重烧成本；现在开工前来现成检索——
看到"3 天前另一台 agent 已经跑通，去掉弯路后最短就这 6 步"，并被告知"你的环境和它差在哪、哪一步要改"。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 抽象 / 基础设施类产品（跨 agent 检索/复用**中间层**，非可视化终端产品本身）。
- 采用的演示方式：纯前端「**模拟体验 + 价值可视化**」，组合三种被允许的形式：
  1. **可搜索面板**：对一个 mock 的"舰队运行 corpus"做意图 + 环境检索（确定性打分，模拟真实系统的 embedding 语义匹配）。
  2. **资源 / 结构视图**：把一条被选中的原始运行"蒸馏"成结构化配方（步骤图 + 弯路折叠 + 来源/验证 + 适配差异）。
  3. **before / after 对比**：左"原始运行（40 步、含 12 步弯路/重试）" vs 右"蒸馏后配方（6 步已验证）"，并可视化"预计省下"。
- 演示的是**我们分析出的创新切入点**（跨 agent 已验证做法的检索与复用），**不是** Construct（运行时服务）或 memory 层的克隆。

## 6. 核心流程（3 分钟内可完成）

1. 进入「检索台」：看到一张"新任务意图卡"（可编辑意图文本 + 环境指纹 chips：如 `框架:Next.js` `目标:部署`
   `平台:Cloudflare`）。点「找现成的」。
2. 面板按匹配度排序返回舰队里的候选运行（每条：匹配分 + 为何匹配 + 是否已验证 + 来自哪台 agent/哪次运行 +
   预计能省多少）。用户理解"哦，舰队里真有人做过"。
3. 点开最高分那条 → 进入「配方视图」：看到蒸馏后的**最短验证路径**（步骤卡），可展开被剪掉的弯路/重试
   （"当时它试错了这 12 步，已为你剪掉"），看到来源、验证方式、以及**适配警告**（你的环境和它差在哪、哪步要改）。
4. 切到「来源与信任」：看一条噪声运行是如何被蒸馏 + 验证成配方的、去重/验证逻辑、以及**诚实的"何时不该复用"**边界。

## 7. 页面结构（<= 3 个主要页面 / Tab）

- 页面 1 · **检索台（Retrieve）**：意图卡 + 环境指纹编辑 + 「找现成的」+ 排序后的候选运行列表（可点选）。
- 页面 2 · **配方（Recipe）**：选中运行的原始 vs 蒸馏 before/after、最短验证步骤、弯路折叠、来源/验证、适配警告、省下估算。
- 页面 3 · **来源与信任（How / Trust）**：蒸馏+验证机制的资源视图、去重逻辑、复用适配规则、诚实边界（何时不该复用）。

## 8. 关键交互

- 编辑意图卡的环境指纹 chips（增删 `框架/目标/平台/语言` 等标签）→ 候选列表的匹配分与排序**实时重算**
  （演示"检索是对意图 + 环境的语义/结构匹配"，且解释每条为何匹配）。
- 切换"只看已验证 / 看全部"过滤。
- 配方视图里点「展开弯路」→ 折叠的 12 步试错展开，直观感受"蒸馏"到底剪掉了什么。
- 顶部一个"舰队规模"滑块（3→50 台）→ "预计每月省下"随规模放大（价值可视化；诚实标注这是基于每条配方的
  单次节省 × 命中频率的 mock 估算，非营销数字）。

## 9. 使用的 mock 数据

全部为 mock，不接真实后端 / 外部 API。结构（`src/data/`）：
- `runs.ts`：一个舰队的 ~10 条历史运行。每条含：`id`、来源 agent、任务意图、环境指纹（框架/平台/语言/目标 标签）、
  原始步骤序列（含标记为 detour/retry 的弯路步）、蒸馏后的最短验证步骤、验证方式（如 "build+smoke 通过"）、
  单次节省估算（省下的 tool-call 数 / 分钟 / 估算 $）。
- `intents.ts`：几个预置"新任务意图卡"（部署到 Cloudflare 边缘 / 修 flaky Playwright / 接 Stripe webhook 沙箱 /
  ESM 迁移 / 接 Postgres），供一键切换体验不同检索结果。
- 检索打分（`src/lib/retrieve.ts`）：确定性函数——意图关键词重合 + 环境指纹标签重合的加权分（0~100），
  并产出"为何匹配"的可解释理由。**明确注明**这是对真实系统 embedding 语义检索的**确定性模拟**。
- 节省估算（`src/lib/savings.ts`）：单条配方省下 = 原始步数−配方步数（tool-call）；分钟/$ 用每步 mock 单价换算；
  舰队月省 = 单次节省 × mock 命中频率 × 舰队规模。全部为带标注的确定性 mock 假设。

## 10. 明确不做什么

- 不做登录 / 用户系统。
- 不接数据库 / 支付 / 外部私钥 / 真实 API / 真实 LLM。
- 不真正运行任何 agent、不真正连接任何运行时（Construct/Epho/VPS 都不连），不产生真实成本。
- 不做生产级后端；所有"语义检索/蒸馏"在前端用确定性 mock 逻辑呈现，并诚实标注为模拟。

## 11. 成功体验标准

- 用户 3 分钟内能说出：它解决什么（别让每台 agent 重学）、怎么用（开工前找现成 → 看蒸馏配方 → 判断能否复用）、
  增量在哪（运行时之上、厂商中立、蒸馏+验证+适配警告，区别于运行时厂商和 memory 层）。
- 用户能亲手改环境指纹并看到匹配结果实时变化，理解"这是对意图 + 环境的检索"，而非一个静态列表。
- 用户在「来源与信任」页能看到诚实边界（何时不该复用），不觉得是过度承诺的营销包装。
