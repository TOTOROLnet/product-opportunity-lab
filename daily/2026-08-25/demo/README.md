# 现成 Xiànchéng — 跨 agent「已验证做法」检索与复用层（Demo）

> 2026-08-25 · product-opportunity-lab 每日机会 Demo
> 纯前端静态原型（Vite + React + TypeScript）。全部数据为 mock，检索 / 蒸馏为**确定性模拟**，
> 不接任何后端 / LLM / 数据库 / 支付 / 登录 / 密钥 / 外部 API，不真正运行任何 agent、不连接任何运行时。

## 这是什么

跑一支自治 AI agent 舰队时（每台 agent 有自己的持久计算环境，如 Construct Computer / Epho / 自建 VPS），
**同一类任务会被 N 台 agent 各自从零重学**——各自踩同样的坑、各自重烧 token 与 sandbox 机时。

「现成」是一个**运行时之上、厂商中立**的复用中间层：新任务开工前先「找现成的」——
检索是否有兄弟 agent 已在相似意图 + 相似环境下**成功做过**，并把那次真实运行
**蒸馏成一条已验证、去噪、去弯路的最短动作配方**直接复用，附来源、逐步验证信号，
以及「你的环境和它差在哪」的**适配警告**。

它**不是** Construct Computer（运行时服务）的克隆，也**不是** memory 层（per-agent 回忆）：
现成不卖算力、不跑 agent，单位是「跨 agent 的已验证配方」而非原始上下文。

## 三个页面（3 分钟看懂）

1. **检索台**：把一张「新任务意图卡」（意图文本 + 可增删的环境指纹 chips）交给现成，
   实时看到舰队历史运行按匹配度排序的结果，每条标注「为何匹配 / 是否已验证 / 复用能省多少 / 几处需适配」。
2. **配方**：点开某条运行，看「原始运行（含弯路/重试） → 蒸馏配方（已验证最短路径）」的 before/after 对比，
   可展开被剪掉的弯路，看逐步验证信号、来源，以及基于你当前环境的适配警告；顶部有省时/省钱与舰队每月潜在节省估算。
3. **来源与信任**：讲清「噪声运行 → 蒸馏 → 验证 → 检索复用」的机制、与运行时/memory/skill 的区别，
   以及**诚实边界**（环境漂移 / 非确定性 / 过期做法 / 未验证≠可信，何时不该盲目复用）。

顶部「舰队规模」滑块（3→50 台）驱动价值可视化：舰队越大，「别让每台电脑重学」省下的越多。

## 本地运行

```bash
npm install     # 安装依赖（React 18 + Vite 5 + TS 5）
npm run dev      # 本地开发，默认 http://localhost:5173
npm run build    # 类型检查 + 生产构建，产物在 dist/
npm run preview  # 预览构建产物
```

## 关键设计

- `vite.config.ts` 设 `base: './'`（相对路径），保证部署到任意 GitHub Pages 子目录（`/2026-08-25/`）都能正确加载资源。
- 检索打分（`src/lib/retrieve.ts`）= 意图关键词重合 55% + 环境指纹标签重合 45% 的**确定性加权**，
  可解释、可复现，用来**模拟**真实系统的 embedding 语义检索；并显式产出「为何匹配」与「适配差异」。
- 价值估算（`src/lib/savings.ts`）= 复用一次省下的步数（原始步数 − 配方步数）× 每步 mock 单价，
  所有单价均为**带标注的假设**，非营销数字。
- 图形（评分环）为**手写 SVG**，无第三方图表库，零额外依赖 / 构建风险。
