# Demo 设计说明 — 2026-07-30

## 1. Demo 名称
收播 Sign-Off — 把你的"稍后读/稍后看"积压，做成一档 AI 主持、每天会结束的节目。

## 2. 一句话定位
你存了几百条永远不看的稍后读；收播的 AI 主持每天从里面挑几条、排成有起承转合的 20 分钟节目、写好串场口播，**放完就收播**——不是又一个刷不完的无限流。

## 3. 目标用户
稍后读/收藏重度用户（Pocket/Readwise/Matter/浏览器书签/YouTube 稍后看），以及被信息流"停不下来又刷得空虚"困扰、想夺回注意力主权的普通人。

## 4. 使用场景
早通勤 / 午休 / 睡前的一段固定时间：打开收播，看今天 AI 给你排的节目单 → 跟着主持一条条读/看 → 到"今日收播"页，看到积压少了几条、可以安心离开，而不是被无限流拖住。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ **可视化/交互类产品**　□ 抽象 / CLI / API / 基础设施类产品
- 采用的演示方式：**直接做可点击的交互 Demo**——一个网页"每日节目播放器"，用户能真正走完 节目单 → 播放（含 AI 串场口播）→ 收播 的完整闭环。
- 演示的是我们分析出的**创新切入点**（AI 当主持而非生成器 + 会结束的有限节目 + 清空你自己的积压），不是被参考产品 SUB/WAVE（直播音乐 DJ）的克隆。

## 6. 核心流程
（用户从进入到"看懂价值"的主路径，3 分钟内可完成）
1. **节目单（Rundown）**：进入即看到今天 AI 编排的节目——总时长、几条、以及一条"起承转合"的弧线（开场暖场 → 深读主菜 → 反调对照 → 轻收尾）；每条卡片显示标题/来源/积压了多久（"存了 47 天"）/预计时长 + 一句 AI 主持"为什么现在给你放这条"。顶部有"积压 128 → 收播后 122"的清空预告。点【开始收播】。
2. **播放器（Player）**：逐条播放。上方是 AI 主持的**串场口播**（承上启下 + 一句"所以呢"），下方是这条内容本身的摘录（来自你自己的积压，AI 不生成正文）；一条**有限进度弧**显示"第 3 / 6 条 · 还剩约 9 分钟"；【读完了 / 下一条】推进，可【跳过】但会被主持轻轻记一笔。**没有无限自动续播**。
3. **收播（Sign-Off）**：放完最后一条进入收播页——"今日节目到此结束"，AI 主持收尾语，三个数字（今天清了几条 / 积压从多少降到多少 / 连续收播天数），一条 before/after 积压条形对比，以及一句刻意反 doomscroll 的话："没有下一条了，去过你的生活吧。"

## 7. 页面结构（<= 3 个主要页面）
- 页面 1：**节目单 Rundown**（首屏，讲清价值 + 编排可见）
- 页面 2：**播放器 Player**（核心体验，AI 主持串场 + 有限进度）
- 页面 3：**收播 Sign-Off**（收尾感 + 积压清空的价值可视化）
（三页用单页应用内的视图切换实现，无路由后端。）

## 8. 关键交互
- 节目单上每条可展开看"AI 为什么现在放这条"。
- 播放器：下一条 / 读完了 / 跳过；进度弧随推进收拢；顶部始终显示"还剩 N 条 · 约 M 分钟"强化"会结束"。
- 收播页：before/after 积压条形动画；"再排一档明天的"按钮（明确写"明天见"，不当场再来一档，强化反无限流）。
- 一个贯穿全局的小开关"主持话痨度"（简洁/正常/健谈）——直观展示"AI 只做主持、可调、不喧宾夺主"。

## 9. 使用的 mock 数据
（全部为 mock，不接真实后端/外部 API）
- `backlog`：约 14–18 条 mock 稍后读条目，字段：`id / title / source / kind(article|video|thread) / savedDaysAgo / minutes / excerpt / tags`。刻意混入"存了很久"的老条目以体现"积压坟场"。
- `program`：今日被 AI 选中的 6 条（引用 backlog 的 id）+ 每条的 `segmentRole(开场/深读/反调/轻收尾)` + `hostIntro`（AI 串场口播，预置文本，模拟生成结果）。
- `hostClosing`：收播收尾语（预置）。
- 统计：`backlogBefore / backlogAfter / cleared / streakDays`。
- 编排逻辑：前端用一个**确定性的**小函数根据 segmentRole 组织弧线与进度，模拟"AI 编排"的结果，保证每次打开一致、可复现。

## 10. 明确不做什么
- 不做登录 / 用户系统。
- 不接数据库 / 支付 / 外部私钥 / 真实 Pocket/Readwise/YouTube API / 任何真实 LLM 调用。
- 不做生产级后端；串场口播是预置 mock 文本（模拟 AI 生成结果），不实时调模型。
- 不做无限流 / 自动续播（这正是产品要反的东西）。

## 11. 成功体验标准
- 用户 3 分钟内能说出："它把我的稍后读积压做成一档 AI 主持、会结束的节目，帮我清积压、还我一个'读完了'的收尾感。"
- 用户能明确感到与"又一个稍后读列表 / 无限信息流"的**体验差异**：编排可见、进度会收拢、结束有仪式感。
- 首屏（节目单）不空白、能立即看懂价值；核心闭环（节目单→播放→收播）可完整走通，无死路。
