闭合。主路径 3 分钟内可跑通：**放映台看初稿 → 导演台逐镜说戏（锁 3 镜 / 改 3 镜）→ 改动预览看 keep-vs-regenerate diff 与成本可视化 → 应用改动回放映台看收敛成片**。锁定镜头在预览与成片里逐字保留，待改镜头按导演笔记被确定性改写并给出「改了什么、为什么」。

## 4. 首屏是否讲清产品价值
清楚。首屏标语直接点明「给『brief→成片』agent 用的导演改稿台 —— 不生成视频，只帮你改」，并以 brief + storyboard 建立「这是一条成片、我在它之上改」的直觉，第一眼就区分于「又一个视频生成器」。

## 5. 交互是否有断点
- 未发现崩溃或死路。`预览改动` 在无「待重生成」镜头时禁用，避免空预览。

## 6. 是否只是概念包装（自嗨检测）
- 是否引用了报告中的具体信号：**是**。切入点直接来自报告事实——Vizard Agent「无时间线 UI + 对话式修改」与报告原话「**留存取决于成片质量与改稿闭环是否顺滑**」，以及 B 类趋势「全流程视频 agent」。
- 是否明确了创新切入点与增量价值：**是**。改稿层（镜头级导演笔记 + 锁定保留 + 选择性重生成 + 成本可视化），相对被参考产品的差异在 `opportunity.md` §5 四项声明与 Demo 的三路对比表里都显式呈现。
- 是否是某产品的照抄：**否**。Demo 刻意**不做视频生成**，只做生成之上的改稿/导演层；与 Vizard（生成流水线 + 聊天框）、CapCut（时间线）在「活/交互原语/价值」三处本质不同。

## 7. Demo 的最大问题
Demo 的「导演引擎」是**脚本化确定性规则**（剪铺垫词 / 插冲击开场 / 高亮强调短语），演示的是**理想形态**。真实产品的最大不确定性在落地：需要上游生成 agent 暴露**镜头级重生成 + 稳定 seed/锁定**能力；现实中不少生成器只能整片重来，「只重生成被点名镜头」可能退化为「局部近似」。这是产品能否成立的关键假设，需早期与真实创作者 + 生成 agent 能力边界验证（已在 `opportunity.md` §6 诚实标注）。

## 8. 是否建议用户人工体验
建议。本次已做自动化 build 验证 + headless 渲染截图，核心路径可信；但「说戏」的价值主要在**交互手感**（锁定的安心感、diff 的可解释、成本对比的说服力），值得人工在浏览器点一遍感受，尤其是「一键填充导演意图 → 预览改动」这条主路径。

## 9. 下一步建议
1. 用真实创作者验证「初稿改稿撞墙」的发生率与付费意愿（证伪「多数人对 80% 初稿就满意」的风险）。
2. 对接一个真实「brief→成片」agent，测「镜头级重生成 + 锁定 seed」在真实后端能做到什么程度，确定「保留承诺」的现实边界。
3. 引擎从规则升级为「意图→镜头重生成指令」的翻译层，并补语气(tone)对正文的真实改写。
