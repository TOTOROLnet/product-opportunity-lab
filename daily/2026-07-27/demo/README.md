# 合流 Héliú — AI Agent 批量变更的联动风险预演台（dry-run + 碰撞检测）

> 2026-07-27 产品机会循环 · 纯前端静态 Demo（Vite + React + TypeScript）

## 这是什么

当电商 / 运营类 AI Agent（如报告里的 **Athena by Shoplazza**）一次性提交**一批**写操作时，
今天的护栏都是「逐条预览、逐条确认」（Athena / Openbase / PureBox 同款）。

**合流的洞见**：逐条预览只验证「单条本身合法」，它在结构上**看不见**多条各自合法的变更
**叠加后**产生的涌现风险 —— 两个促销叠成深折、改价 + 无条件包邮跌破成本、
促销覆盖了被本批清零库存的商品、一刀切品类迁移让常规款意外获得清仓折扣。

> 整体的危险 > 逐条预览之和。

合流把整批变更**物化**成结果状态，做一次 **dry-run**，检查 5 类业务不变量，
抓出「叠加后才违规」的**碰撞（clash）**，让人在**计划层**（而非单条层）剔除 / 保留，
并给出**单一原子回滚点**。

## 场景（Demo 内置）

商家说：「为夏季清仓大促做准备：过季夏装打折、爆款加量、统一包邮门槛、清理断码 SKU。」
Agent 生成 **12 条**写操作：

- 逐条预览：**12 / 12 通过**（每条各自合法）。
- 合流 dry-run：检出 **7 处联动风险**（3 高危），涉及 3 个亏损 / 负毛利在售 SKU、
  2 个促销指向无货商品、1 处促销超叠加、1 个常规款被误扫入清仓促销。
- 一键剔除 **4 条**「全局 / 一刀切」操作（无条件包邮、全场 VIP 叠加、一刀切迁品类、促销期清零在促库存）
  → 联动风险归零，剩 8 条安全执行。

## 三个页面

1. **① 变更计划（逐条视图）**：Agent 提交的 12 条变更卡片，逐条预览全绿 —— 复现今天主流护栏的形态。
2. **② 联动风险（合流视图）**：整批 dry-run 后的 7 处涌现冲突，每处含「单看 vs 叠加后」对比与卷入的变更项；顶部是 5 类不变量体检。
3. **③ 决策与回滚**：逐条剔除 / 保留（实时复算）、一键应用推荐剔除、「照单全批 vs 当前计划」对比表、单一原子回滚点。

## 运行方式

```bash
npm install      # 安装依赖
npm run dev      # 本地开发（默认 http://localhost:5173 ）
npm run build    # 生产构建，产物在 dist/
npm run preview  # 预览构建产物
```

## 技术与边界

- 技术栈：Vite + React 18 + TypeScript；`vite.config.ts` 设 `base: './'`，可部署到任意 Pages 子目录。
- 引擎：`src/logic/engine.ts` 为**确定性业务规则**（物化批次 → 算叠加折扣 / 毛利 / 库存 / 包邮 → 列出冲突）。
  同一引擎驱动三个页面，所有数字均可复算，与页面显示一致。
- **明确不做**：登录 / 用户系统、数据库、支付、外部私钥、真实电商后台、真实 API、真实 LLM、真实回滚写入。
- **AI 核心度（诚实说明）**：冲突检测引擎是确定性规则，不是「AI 自己判断」。
  AI 核心在于：(a) 这个问题只因「AI Agent 有批量写权限」才存在；(b) 真实产品会用 LLM 推断非显式的语义级联动。
  Demo 只演示可确定复算的部分，是对真实产品的保守下界表达。

## 与被参考产品的区别（非克隆）

- **不是 Athena / Openbase / PureBox**：它们是「逐条预览确认」，粒度在单条，看不见组合风险；
  合流是「整批 dry-run + 涌现冲突检测 + 计划级决策」，防的是「一堆各自没错的写操作合起来把毛利 / 库存 / 促销规则搞崩」。
- 是这类执行型 Agent 的**安全前置层**，不是又一个电商运营 Agent。
