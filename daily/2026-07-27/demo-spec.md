# Demo 设计说明 — 2026-07-27

## 1. Demo 名称
合流（Héliú）— AI Agent 批量变更的联动风险预演台（dry-run + 碰撞检测）

## 2. 一句话定位
在 AI 运营 Agent 把一批改动写进真实业务系统之前，先把整批一起算清后果，抓出「每条各自合法、叠加后违规」的联动冲突，让人在计划层而不是逐条层拍板。

## 3. 目标用户
用 AI Agent（如 Athena 这类电商运营 Agent）直接对真实业务系统做批量写操作的商家 / 运营 / 平台方；以及想给「Agent 批量写」加安全轨道的 Agent 平台团队。

## 4. 使用场景
商家对电商运营 Agent 说：「为夏季清仓大促做准备：过季夏装打折、爆款加量、统一包邮门槛、清理断码 SKU。」Agent 生成 12 条写操作。逐条预览每条都合法（全绿），但合起来会让 3 个 SKU 跌破成本、1 个促销覆盖了被本批置零库存的商品、1 处品类迁移导致意外叠加资格。合流在执行前把这些涌现风险算出来。

## 5. Demo 策略分型（重要）
- 本机会属于：☑ 抽象 / CLI / API / 基础设施类产品（Agent 批量写的安全前置层）
- 采用的演示方式：纯前端「**模拟体验 + 价值可视化 + before/after 对比**」。
  - 用一个 mock 的「Agent 提交的 12 条批量变更」作为输入；
  - 一个**确定性引擎**物化批次结果、计算 4 类业务不变量、列出涌现冲突；
  - 用 before/after 直观对比「逐条照单全批」vs「计划级复核」的净后果差异。
- 演示的是**我们分析出的创新切入点**（整批 dry-run + 涌现冲突检测 + 计划级决策），不是 Athena / PureBox 的克隆（它们是逐条预览确认）。

## 6. 核心流程（3 分钟内看懂价值）
1. 进入 **① 变更计划（逐条视图）**：看到 Agent 提交的 12 条变更卡片，每条各自「预览通过 ✅」——横幅点明「逐条预览：12/12 通过 ≠ 安全」。（这正是 Athena 的护栏形态，用来做反差铺垫。）
2. 切到 **② 联动风险（合流视图）**：引擎列出 4 处涌现冲突，每处显示「涉及哪几条变更 + 违反的不变量 + 叠加前后数值（如 草编帽 每项看着 OK，叠加后 ¥59.0 < 成本 ¥62，每单亏 ¥3）+ 严重度」；顶部是 4 类不变量的体检卡。
3. 切到 **③ 决策与回滚**：一键剔除 / 调整被标红的变更 → 引擎实时复算 → 冲突归零；给出「照单全批 vs 计划级复核」对比表（亏损 SKU 3→0、漏检联动风险 4→0、需人工决策项 12→2）与单一原子回滚检查点。

## 7. 页面结构（<= 3 个主要页面，单页 Tab 切换）
- 页面 1：变更计划（逐条视图）——12 张变更卡 + 「逐条全绿」横幅。
- 页面 2：联动风险（合流视图）——涌现冲突清单 + 4 类不变量体检 + 每处冲突的 before/after 数值与涉及项。
- 页面 3：决策与回滚——可勾选剔除标红项、实时复算、before/after 对比表、价值卡、回滚检查点。

## 8. 关键交互
- Tab 切换三视图；三视图由**同一个确定性引擎**驱动（保证数字一致、可复算）。
- 页面 3 勾选 / 取消勾选「剔除」某条变更 → 冲突数、亏损 SKU 数、对比表实时重算。
- 冲突卡点击可高亮它涉及的变更项编号。

## 9. 使用的 mock 数据
- 一个 mock 商品目录（约 6 个 SKU：草编帽 / 亚麻衬衫 / 凉鞋各码 / 断码 T 恤 等，含成本、原价、库存、所属品类）。
- 一批 mock 的 Agent 变更（12 条：改价、按品类设促销、单品叠加促销、VIP 客群促销、包邮门槛、库存增减 / 置零、品类迁移、清仓品类满减）。
- 4 类业务不变量：①价格不低于成本（含叠加折扣后）②促销叠加深度 ≤ 阈值 ③促销商品必须有库存 ④包邮后毛利仍为正。
- 全部为 mock，不接真实后端 / 数据库 / 支付 / 登录 / 外部 API / LLM。

## 10. 明确不做什么
- 不做登录 / 用户系统
- 不接数据库 / 支付 / 外部私钥 / 真实 API / 真实电商后台 / 真实 LLM
- 不做生产级后端
- 不做真实撤回（回滚检查点为可视化示意）
- 不声称引擎是「AI 判断」——它是确定性业务规则；AI 核心在于这个问题因 Agent 批量写而生（见 opportunity.md 第 6 节）

## 11. 成功体验标准
- 用户 3 分钟内能说出：它解决什么（逐条预览看不见的批量联动风险）、怎么用（整批 dry-run→看冲突→计划层剔除→安全执行 + 回滚点）、增量在哪（per-action → plan-level，抓涌现冲突）。
- before/after 对比可用确定性引擎复算验证（亏损 SKU 3→0、联动风险 4→0）。
