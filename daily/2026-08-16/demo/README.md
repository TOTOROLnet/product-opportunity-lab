# 闸口 Zhākǒu · Sluice — Agent 动作策略的「爆炸半径」上线前预演台

> Blast-Radius Preflight for Agent Action Policies
> 纯前端静态 Demo（Vite + React + TypeScript）· 全 mock · 无后端 / 无 LLM / 无真实 agent 运行时

## 这是什么

给 coding/ops agent 车队配了真实工具权限（shell / git / 云 API / 数据库 / 支付 / 外发…）后，**上线前**你其实看不清：这套护栏策略到底会让 agent 自己干哪些不可逆的事？多少要叫人？有没有动作根本没规则命中、走了默认放行？

**闸口**把这件事变成一个可玩的预演台：编辑一套厂商中立的护栏策略 → 对一份 12 条的「agent 拟执行动作」语料做确定性回放 → 直接看到**爆炸半径**、**漏网不可逆动作**、**人审负载 vs 预算**、**策略盲区**，并与「宽松基线」做 before/after 对比。

它**不是**运行时守卫（那是 Phinq 一类产品的活）。它是**设计期**的 what-if 模拟器 + 策略 linter——帮你在出事前把策略调对。

## 核心概念

- **判决（三态）**：✅ 自动放行 / 🙋 叫人复核 / ⛔ 一票否决（fail-closed）。每条判决都可解释（命中了哪条规则 / 守卫）。
- **爆炸半径**：只统计**被自动放行**的动作——上线后 agent 能自己干、没人盯着的部分。不可逆 + 涉敏感数据 + prod/external 范围越多，半径越大。
- **漏网不可逆/敏感动作**：被自动放行、却是不可逆或涉 PII/密钥的动作数——策略最该归零的指标。
- **人审负载 vs 预算**：叫人复核的条数。太多 = 告警疲劳，太少 = 漏风险，需要权衡。
- **策略盲区**：无任何规则/守卫命中、只能走「默认路径」处置的动作。默认放行则危险，默认否决则误伤。

## 三个页面

1. **策略台**：预设（宽松 / 均衡 / 严格）+ 全局守卫开关 + 风险阈值/人审预算滑杆 + 默认路径 + 8 类工具分类规则。任意改动，顶部指标即时刷新。
2. **回放**：逐条动作的判决 + 可解释理由；可筛选「只看危险漏网」。
3. **爆炸半径 & 盲区**：可逆×影响面的爆炸半径矩阵（红区 = 上线后能自己炸的范围）+ 自动放行动作按半径排序 + 与宽松基线的 before/after + 策略盲区清单。

## 3 分钟体验路线

1. 打开即为「均衡」策略：看顶部——爆炸半径已比宽松基线小很多、漏网为 0，但人审略超预算。
2. 点「宽松」：看爆炸半径飙升、漏网变多（含删库 / 退款 / 密钥外发被自动放行）——这就是「先开着再说」的代价。
3. 点「严格」或手动打开各守卫：漏网归零、爆炸半径压到 0，但人审负载顶满、连 draft PR 都被默认否决——直观感受「安全 vs 告警疲劳」的真实权衡。

## 本地运行

```bash
npm install
npm run dev      # 本地开发预览
npm run build    # 产出到 dist/（部署用）
npm run preview  # 本地预览 build 产物
```

- `vite.config.ts` 设 `base: './'`，部署到任意 GitHub Pages 子目录（`/<date>/`）都能正确加载资源。

## 数据与边界

- `src/data/mock.ts`：12 条 mock 动作 + 3 套预设策略，所有属性（可逆性 / 数据敏感度 / 影响面 / 基础风险）为人工标注。
- `src/engine.ts`：确定性护栏引擎（纯函数、可解释、可复现）。
- **不接**：真实 agent trace / LLM 风险分类 / 后端 / 数据库 / 支付 / 密钥 / 登录 / 外部 API。
- Demo 演示的是「设计期策略预演」的**价值形态**，mock 判定精度不代表生产级。
