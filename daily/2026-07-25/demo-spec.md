# Demo 设计说明 — 2026-07-25

## 1. Demo 名称

火候 Huohou —— 微调/蒸馏前的决策与数据预检台

## 2. 一句话定位

在你按下「一键微调」之前，火候基于你已有的前沿模型调用轨迹，先替你判断**该不该训、训哪一片、数据够不够、值不值**——并对大多数任务诚实地给出「别训」。

## 3. 目标用户

正在评估「上小而专模型省钱提速」的 AI 应用团队 / 平台工程 / 独立开发者——手里有一堆前沿模型调用轨迹，却不确定是否该 fine-tune、该训哪片、数据够不够。

## 4. 使用场景

团队看到 Freesolo Flash 这类「一键后训练」很心动，准备把若干任务都微调成小模型。用火候把真实用量轨迹导入，先做一次训练前预检：哪些任务其实只需 prompt/RAG/换路由（不该训）、哪一两片真正值得蒸馏/微调、这些片子的数据够不够干净、训完每月能省多少、多久回本，最后导出「只把该训的片子」交给训练平台的清单。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 抽象 / CLI / API / 基础设施类产品（模型专门化决策，无可视界面原型）
- 采用的演示方式：纯前端「**模拟体验 + 价值可视化**」——
  - **用量画像**：把 mock 调用轨迹语料呈现为任务分片卡片（资源视图）；
  - **决策台**：对每个分片跑确定性 lever 引擎，给出建议 + 可训练性评分 + 数据集预检 + ROI（模拟核心工作流）；
  - **组合前后对比**：before（全量前沿 / 盲目全训）vs after（只训该训的）→ 省多少钱、快多少、少多少返工（before/after 对比）。
- 演示的是**我们分析出的创新切入点**（训练前决策与数据预检），不是 Freesolo Flash（训练执行）的克隆。

## 6. 核心流程（用户 3 分钟内看懂价值）

1. 进入 **① 用量画像**：看到 6 个真实感任务分片（工单分类、KB 问答、合同风险摘要、营销文案改写、docstring 生成、意图澄清），每片标注月调用量、单价、延迟、返工率、失败信号构成、可用 gold 样本数——一眼看出「钱和错误集中在哪」。
2. 进入 **② 决策台**：选任一分片（或看全部），火候给出：
   - **lever 建议**（prompt / RAG / 路由 / 微调LoRA / 蒸馏 五选一）+ 一句归因理由（基于主导失败信号）；
   - 对「建议训练」的片子：**可训练性评分（0–100）** + 分项（量/省幅/稳定性/数据充足度）；
   - **数据集预检**：gold 样本 →（去重/去 PII/去泄漏后）可用样本数、是否够、还差多少；
   - **ROI 投影**：期望质量保持、延迟下降、每月省多少、一次性训练成本、回本天数、GO / 需补数据 / 别训。
3. 进入 **③ 组合与产出**：并排对比 before（全部跑前沿 / 或盲目把 6 片全微调）与 after（按建议：2 片蒸馏 + 1 片微调 + 1 片 RAG + 1 片 prompt + 1 片保持前沿），展示每月总成本、加权延迟、返工率的改善；并生成**「训练清单」**——只把该训的分片 + 清洗后的数据集规模，导出成可交给 Freesolo 这类平台的 TOML 预览。

## 7. 页面结构（<= 3 个主要页面 / Tab）

- 页面 1 **用量画像**：任务分片卡片网格 + 失败信号迷你条 + 「钱/错集中处」高亮。
- 页面 2 **决策台**：分片选择器 + lever 建议卡 + 可训练性评分环/条 + 数据集预检 + ROI 投影 + GO/别训裁决。
- 页面 3 **组合与产出**：before/after 价值条（成本/延迟/返工）+ 「别训的片子省下的浪费」高亮 + 训练清单 & TOML 预览。

## 8. 关键交互

- 分片切换：点卡片即在决策台切换该分片的引擎输出（响应式重算，非硬编码）。
- 「盲目全训」对照开关：在组合页切换 after 的基准——「按火候建议」vs「跟风把 6 片全微调」，直观看出后者反而更贵/更慢（有些片子微调根本不省，甚至因数据不足质量掉）。
- 数据充足度联动：对 gold 不足的片子，裁决从 GO 变为「需补 N 条数据」，ROI 相应显示延后回本。
- 所有数字来自 `src/logic/engine.ts` 对 `src/data` mock 轨迹的确定性计算，可在页面上看到分项拆解（不是魔法数字）。

## 9. 使用的 mock 数据

- `src/data/traces.ts`：6 个任务分片，每片含月调用量、平均输入/输出 token、前沿模型单价、平均延迟、返工率、稳定性、可用 gold 样本、数据卫生（重复率/PII/泄漏）、失败信号分布（缺知识 / 指令歧义 / 格式漂移 / 推理错误 / 正确但太贵慢）。
- 数据为**手工构造的真实感 mock**，刻意让 6 片落在不同 lever（2 蒸馏 / 1 微调 / 1 RAG / 1 prompt / 1 保持前沿），以证明「不是所有任务都该训」。
- 全部为 mock，不接真实后端 / 训练平台 / 外部 API。

## 10. 明确不做什么

- 不做登录 / 用户系统
- 不接数据库 / 支付 / 外部私钥 / 真实 API / 真实训练或 GPU
- 不做生产级后端
- 不真的训练模型、不调用任何 LLM——所有「决策 / 评分 / ROI」均为确定性规则的模拟

## 11. 成功体验标准

- 用户 3 分钟内能说出：火候解决什么（训练前的决策与数据预检）、怎么用（画像→决策→组合）、增量在哪（对多数任务说「别训」，只对值得的片子备数据算 ROI，与「一键训练一切」反向）。
- 能亲眼看到「盲目全训」比「按火候建议」更贵/更慢的对照，理解诚实决策的价值。
- 能看清每个数字的分项来源，感到结论可复算、可信、不自嗨。
