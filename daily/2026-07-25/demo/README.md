# 火候 Huohou — 微调/蒸馏前的决策与数据预检台

> 在你按下「一键微调」之前，火候基于你已有的前沿模型调用轨迹，先替你判断
> **该不该训 · 训哪一片 · 数据够不够 · 值不值**——并对大多数任务诚实地给出「别训」。

这是 `product-opportunity-lab` 2026-07-25 的每日机会 Demo。riding 报告里的 **Freesolo Flash**
（15/18，让编码 agent 一键完成小模型后训练）与趋势 #3「小而专 + 省 token/算力」，
但**不是它的克隆**：Freesolo 是训练**执行层**；火候是它的**互补上游**——训练前的决策与数据/评测预检。

## 它解决什么

一键训练时代最大的浪费不是「训练难」，而是：
1. 在**不该训**的任务上盲目微调（其实只需 prompt/RAG/换路由）；
2. 用**脏/不足**的数据训（重复、PII、泄漏、样本不够）；
3. **训完才发现**没省钱 / 质量掉。

火候站在你的调用轨迹上，先做训练前预检，把最容易翻车的一步补上。

## 三个页面（3 分钟看懂）

1. **① 用量画像**：7 个 mock 任务分片的月成本、返工率、稳定性、gold 样本与失败信号构成——看清「钱和错误集中在哪」。
2. **② 决策台**：对每片给出 **lever 建议**（Prompt/RAG/难度路由/微调 LoRA/蒸馏 五选一 + 保持前沿）、
   可训练性评分（量×省幅×稳定性×数据充足度）、数据集预检（gold→去重/去PII/去泄漏→可用）、
   ROI 投影（省多少/延迟/回本），裁决 GO / 需补数据 / 别训。
3. **③ 组合与产出**：before（全前沿）/ after（火候建议 vs 跟风全训）对比，并生成只含「该训片子」的训练清单 TOML。

**核心结论**：7 片里只有 **3 片值得训练**（2 蒸馏 GO + 1 微调需补数据），其余 4 片建议别训。
「跟风把 7 片全微调」账单看着更省，返工率却飙到最高、还白烧一倍训练费、把高风险片子交给小模型——省小钱担大险。

## 运行方式

```bash
npm install      # 安装依赖
npm run dev      # 本地开发（默认 http://localhost:5173）
npm run build    # 生产构建，产物在 dist/
npm run preview  # 预览构建产物
```

## 技术与约束

- 技术栈：Vite + React + TypeScript。`vite.config.ts` 设 `base: './'`，可部署到任意 Pages 子目录。
- 所有「决策 / 评分 / ROI / 组合对比」均由 `src/logic/engine.ts` 对 `src/data/traces.ts` 的 mock 轨迹
  **确定性计算**得出，页面上可看到分项拆解（非魔法数字）。
- **不训练、不碰 GPU、不调任何 LLM**；无后端 / 无登录 / 无数据库 / 无支付 / 无外部 API。
