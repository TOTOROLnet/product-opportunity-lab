## 2. 候选机会（至少 3 个，均为创新切入点而非照抄）

### 候选 A：有数 Yǒushù —— 诚实的端侧实时动作教练（看得见才教，练到心里有数）

## 4. 深入论证（针对选中机会）

1. 目标用户：在家或健身房**独自训练**、请不起私教、跟着视频练没人纠错的普通健身者与新手；他们最怕两件事——**动作错了受伤**、和**练了个寂寞（自以为练到位其实没到）**。
2. 核心痛点（真实、高频、可付费）：现有端侧 CV 教练把「实时反馈」等同于「不停地数、不停地纠、不停地夸」。但摄像头会被机位/遮挡/速度限制——当它其实**看不清却自信地喊「膝盖再外一点」**，在健身里等于**教你错误发力**；当它把你**硬撑的垃圾次数也数进去、还夸你**，你以为在进步其实在磨坏动作。这个「自信的错」比「没有教练」更糟，且报告亲口把它列为**生死线**。willingness-to-pay 存在：订阅制健身 App 已被验证可付费，差异化就在「值不值得信」。
3. 现有产品为什么没解决好：同类（CoachAI/trainerai 等）在**覆盖率与参与度**上军备竞赛（数得更准、纠得更多、夸得更勤），因为那是最容易做 demo、最像「智能」的方向；**没有人愿意让产品承认「这一下我看不清」**——那看起来像「不够聪明」。但恰恰是这份**诚实**，才是信任与留存的来源。这是一个被集体回避的空白。
4. 为什么适合做轻量 Demo：核心是「关节数据 → 逐次置信度/达标判定 → 达标计数/看不清拒答/疲劳喊停 → 讨好 vs 有数 对照 → 诚实周报」的**确定性**链路，全部可 mock（用脚本化关节角度序列模拟端侧 CV 输出）；无需真实摄像头/模型/后端；一个会动的骨架 + 两行对照就能让人 3 分钟看懂「解决什么/怎么用/增量在哪」。

## 5. 不照抄声明（四项必填）

1. 创新切入点是什么：**把「感知置信度」而非「纠错覆盖率」做成实时动作教练的第一原则**——看得见才教、看不清就明说且不瞎数不瞎纠、动作垮了就喊停；用「诚实 + 剂量」替代同类的「数满 + 讨好」。
2. 解决的具体问题/场景：端侧 CV 教练在机位/遮挡/速度受限时**看不清却自信乱纠**（健身里 = 教错发力甚至受伤）、并把**硬撑的垃圾次数也数进去还夸你**（虚荣进步）。有数 用逐次置信度、可信计数、疲劳喊停补上这段空白。
3. 相对被参考产品（CoachAI）的增量价值（差异点）：CoachAI 卖的是**覆盖率**（数每一次、实时纠每一次）；有数 卖的是**可信度**（只教它真看清的、明说看不清的、并在该停时喊停）。前者最大化「教练在场感」，后者最大化「教练值得信」；后者顺带把留存从「热情期」问题变成「信任」问题。
4. 为什么这不是照抄 CoachAI（本质区别）：二者的**目标函数相反**——CoachAI 追求「尽可能多地数与纠」，有数 追求「只在能真正看清时才教、并诚实暴露自己的感知边界与剂量建议」。CoachAI 的失败模式（看不清却乱纠、虚荣计数）正是有数 的**核心功能**要消除的东西。这是**覆盖率产品 vs 可信度产品**的关系，动机与产品面相反，不构成克隆。它也不是 07-28 验己（那是事后对生活方式做 n-of-1 诚实读数，本产品是训练当下的实时感知诚实与剂量），域与时机都不同。

## 6. 不确定性与风险

- 需求侧风险：普通用户可能**更爱被讨好**——一个会说「我看不清 / 你该停了」的教练，短期爽感不如「great job! 12/12」。诚实是否真能转化为留存与付费，是这条价值假设里我最不确定的一环，如实标注；有数 更可能靠「少受伤、真进步」的中长期口碑，而非首日爽感获客。
- 落地/技术风险：真实版的核心难点恰恰是**「置信度本身要准」**——端侧姿态估计要能可靠地判断自己何时不可靠（不确定性估计），这本身是硬 AI 问题；Demo 用脚本化关节数据 + 确定性规则**模拟**这层置信度，真实系统的置信度校准质量是另一道难题。复杂/器械动作的鲁棒性（报告也点到）在真实版更难。
- 我可能判断错的地方：①也许「诚实承认看不清」在消费端反而劝退用户，覆盖率型产品才是市场想要的；②置信度门槛设太高会「什么都不敢教」变得没用、太低又回到乱纠，这个平衡点可能很窄；③健身留存的根本问题（懒、没动力）也许不是「教练值不值得信」能救的。Demo 目标是**把这条价值假设讲清并可体验**，而非断言它一定成立。
