# Demo 设计说明 — 2026-08-04

## 1. Demo 名称

**有数 Yǒushù** —— 诚实的端侧实时动作教练（看得见才教，练到心里有数）

## 2. 一句话定位

一个把「感知置信度」而非「纠错覆盖率」做成第一原则的端侧 CV 健身教练：**看得见才教、看不清就明说且不瞎数不瞎纠、动作垮了就喊停**——用诚实与剂量，替代同类的数满与讨好。

## 3. 目标用户

在家/健身房独自训练、请不起私教、跟着视频练没人纠错的普通健身者与新手；最怕「动作错了受伤」和「练了个寂寞」。

## 4. 使用场景

架好手机 → 开练。摄像头当动作传感器，逐次判断「我看清了没 / 达标没 / 你是不是该停了」。练完得到一份**只算可信次数**的诚实进度，而不是虚荣总次数。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 可视化/交互类产品（端侧 CV 实时反馈本身是抽象/硬件依赖能力，故采用「**模拟体验 + 价值可视化**」——脚本化关节数据回放，而非真开摄像头）。
- 采用的演示方式：
  - **网页版「实练回放」**：用脚本化的逐帧关节角度序列（mock 端侧 CV 输出）驱动一个**会动的 SVG 骨架**，逐次 rep 播放，实时显示置信度与教练气泡。
  - **before/after 对照**：同一组训练在「讨好型教练」与「有数」两种策略下的**逐次对照**，直观展示信任/受伤风险差。
  - **诚实进度可视化**：用同一引擎跑一周 mock 训练，展示「你以为的次数 vs 可信次数」与真实动作质量趋势。
- 演示的是**我们的创新切入点（诚实 + 剂量）**，不是 CoachAI 的克隆（它追求覆盖率，我们追求可信度）。

## 6. 核心流程（3 分钟内看懂价值）

1. 进入 **① 实练台**：点「开练」，骨架开始做深蹲，逐次出现教练判定——达标 ✓ / 姿势提醒（含哪块关节、为什么）/ **「我看不清，先调机位」（不计数、不瞎纠）** / 到疲劳那一下**喊停**。右侧「看得清吗」置信度条实时起伏，计数器只加**可信达标**的次数。
2. 切到 **② 讨好 vs 有数**：同一组 12 次并排对照——讨好型数满 12、对看不清的 3 次也自信乱纠、从不喊停；有数只认看清的、明说看不清的、第 9 次喊停。下方汇总「报的次数 / 看不清却硬纠(受伤风险) / 是否喊停」。
3. 切到 **③ 诚实进度**：一周汇总——每天「以为的次数 vs 可信次数」的水分条 + 动作质量中位数趋势 + 一段**诚实读数**（真进步在哪、虚荣水分多少、下周建议），全部由同一引擎算出。

## 7. 页面结构（<= 3 个主要页面）

- 页面 1 · **实练台 (Coach)**：会动的 SVG 骨架 + 置信度条 + 可信计数器 + 逐次教练气泡日志 + 开练/单步/重播控制。
- 页面 2 · **讨好 vs 有数 (Compare)**：同一组两条逐次色带 + 汇总统计卡（报的次数 / 盲纠次数 / 是否喊停 / 可信达标）。
- 页面 3 · **诚实进度 (Progress)**：一周「以为 vs 可信」水分条 + 深度质量趋势折线（SVG）+ 诚实读数段落。

## 8. 关键交互

- **开练/单步/重播**：驱动骨架逐帧动画（requestAnimationFrame/interval），每完成一次 rep 追加一条教练判定。
- **置信度条实时变化**：看不清的 rep 置信度掉到阈值下，骨架关节变虚 + 出「?」，教练气泡变为「看不清 + 调机位建议」。
- **喊停高亮**：到疲劳衰减那一次，界面出现醒目「该停了」卡片，其后的次数在计数器里被标为「未计（硬撑）」。
- **对照带 hover/点击**：查看讨好 vs 有数 对每一次 rep 的不同处理。
- 全部为确定性计算，任何时候点开都得到一致结果（便于自测与复现）。

## 9. 使用的 mock 数据

- `src/data/sessions.ts`：
  - 今日主演示 session「深蹲 1 组 × 12」：每次 rep = { 深度角、膝内扣、下放节奏、可见性(clear/机位/遮挡/太快) }，脚本化覆盖：达标、膝内扣提醒、机位看不清、遮挡看不清、太快看不清、以及后半段疲劳掉深度→喊停。
  - 一周 7 天 mock sessions（含深蹲/俯卧撑等），供进度页聚合。
- `src/logic/engine.ts`：确定性引擎——逐 rep 置信度、达标/看不清/纠正判定、疲劳喊停点、讨好 vs 有数 对照统计、一周聚合与诚实读数。**所有数字由引擎算出，非手写**（已用一次性脚本预校验）。
- 骨架姿态由深度/膝内扣参数 + 动画相位参数化生成，非录制视频。

## 10. 明确不做什么

- 不开真实摄像头、不接真实端侧 CV 模型、不做真实姿态估计。
- 不做登录 / 用户系统。
- 不接数据库 / 支付 / 外部私钥 / 真实 API / LLM。
- 不做生产级后端；视频/数据「不出本机」在 Demo 里是叙事，不涉及任何真实数据流。

## 11. 成功体验标准

- 用户 3 分钟内能说出：「它解决什么（看不清却乱纠 + 虚荣计数）、怎么用（架手机开练、逐次诚实判定）、增量在哪（可信度而非覆盖率：会说『我看不清』和『你该停了』）」。
- 能亲眼看到「讨好型数满 12 且盲纠 3 次」与「有数只认 X 次、明说看不清、第 9 次喊停」的差别。
- 首屏即讲清「看得见才教」的第一原则，不需要解释就能感到它「诚实」。
