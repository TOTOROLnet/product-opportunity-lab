# Demo 设计说明 — 2026-08-23

## 1. Demo 名称

**编谱 Biānpǔ — 面向 coding agent 的语义改动谱编排台（Semantic Change Composer）**

## 2. 一句话定位

把「让 agent 改代码」从一句藏着歧义的散文指令，升级成**人能编排、agent 能精确演奏**的结构化「改动谱」，并导出无歧义、机读的交付清单。

## 3. 目标用户

重度使用 coding agent（Cursor / Claude Code / 各类 harness）做**跨文件结构性重构**的开发者与团队负责人——最常在「一句话交给 agent → 少改/错改/过度改 → 反复纠偏」上损耗的人。

## 4. 使用场景

你要在 `acme-checkout` 这个（mock）支付服务里做一次结构性重构：给某函数换个更清楚的名字、给某请求函数加 `options`、把重试逻辑抽成独立能力、金额统一改用 `Cents` 类型。过去你会把这句话直接甩给 agent；现在你先在编谱里把它编排成一份谱，看清每个操作展开成的确切编辑，再把无歧义清单交给 agent。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 可视化/交互类产品（一个**确定性语义图引擎 + 交互编排台**）　☐ 抽象/CLI/基础设施类产品
- 采用的演示方式：**直接做可点击交互 Demo**。在一份手工构造、可信的 mock 代码库（符号 + 引用 + 调用边）上，让用户增删语义操作、切换关键参数，**实时**看到改动谱的展开、编辑集合与「歧义消除」收益，并渲染「一谱三读」的交付产物。
- 演示的是**我们分析出的创新切入点**（人在意图空间编排、agent 拿无歧义清单执行），不是被参考产品的克隆（不是 Zero 新语言、不是 IDE 单点重构、不是让 agent 直接吃散文）。

## 6. 核心流程（用户 3 分钟内可完成「看懂价值」）

1. **进入「编排台」**：左侧是 mock 代码库的符号视图；顶部是一句典型的**散文重构指令**，标出其中藏着的 4 处「未拍板决策 / agent 只能猜」。
2. **把散文编排成谱**：从操作面板启用/停用语义操作（重命名、改签名+传播、抽取能力、改类型），并对关键歧义点**拍板参数**（如 `opts` 必填/选填、Cents 改动范围）。每次改动，右侧「改动谱」与顶部「歧义消除 / 待猜点数」实时重算。
3. **看展开与交付**：切到「演奏预览」查看某个操作展开成的确切语义编辑（触达的符号/引用/文件 + 执行顺序，0 处需猜）；再切到「一谱三读」看同一份谱的三种投影——给人的白话摘要、给 agent 的机读 manifest（JSON）、结构变更预览——直观感受「一份真相、多种读者」。

## 7. 页面结构（<= 3 个主要页面，单页 + 三个 Tab）

- **Tab 1 · 编排台（Compose）**：mock 代码库符号视图 + 散文指令的歧义高亮 + 语义操作面板（启停 + 参数拍板）+ 实时「改动谱」概览 + 顶部收益指标条（待猜点数 / 歧义消除 / 触达文件·引用数）。
- **Tab 2 · 演奏预览（Perform）**：选中某操作 → 展开成有序的确切语义编辑列表（每条：目标符号 / 所在文件 / 动作 / 是否自动传播的调用点），并显式标注「本操作 agent 需猜测处 = 0」。
- **Tab 3 · 一谱三读（One Score, Three Readers）**：同一份谱的三投影切换——① 白话摘要（给人复核）② agent manifest（typed ops JSON，含稳定符号 id / 顺序）③ 结构变更预览（按文件的结构级增删改，非逐行 diff）；底部含「散文 vs 谱」对照与「非照抄」说明。

## 8. 关键交互

- 操作启停开关（4 个语义操作）→ 全局指标与谱实时重算。
- 歧义参数拍板：`postJson` 的 `opts` **必填/选填**切换（改变需传播的调用点数）；`Cents` 改类型**范围**切换（仅 charge / charge+refund / 全部金额，改变触达引用数）——直观展示「同一句散文里，人本该拍板、否则 agent 只能猜」的决策。
- Tab 2 点击任一操作查看展开明细；Tab 3 三种投影一键切换 + 复制 manifest JSON。

## 9. 使用的 mock 数据

- 全部为**手工构造的确定性 mock**，模拟一个小型 TypeScript 支付服务 `acme-checkout` 的语义图：
  - 文件（约 8 个）：`src/payments/gateway.ts`、`src/payments/retry.ts`、`src/api/handlers.ts`、`src/api/client.ts`、`src/util/money.ts`、`src/audit/log.ts`、`tests/gateway.test.ts` 等。
  - 符号：函数（`charge` / `refund` / `postJson` / `withRetry` / `formatCents` …）、类型（`ChargeResult` / `RetryOpts` …），每个符号带**确切引用位置与调用边**。
  - 4 个语义操作与其展开规则、执行顺序、随参数变化的触达数，全部由确定性引擎（`engine.ts`）根据这份图计算，**不接任何真实后端 / LLM / 外部 API / 数据库 / 支付 / 登录 / 密钥**。
- 关键展开数字（引擎 `engine.ts` 计算、UI 显示，均已用 `_verify.ts` 预验；默认全启用 + 默认参数）：
  - 重命名 `charge → createCharge`：定义 1 + 引用 7 = **8 处**（顺调用边找全部引用，非文本替换）。
  - 改签名 `postJson(url, body) → (url, body, opts?)`：**选填**（默认）= 定义 **1 处** + 9 处调用点**自动判定兼容、0 改动**；切成**必填**则 = 定义 1 + 补参数 9 = **10 处**。这正是散文「支持一下 options」没拍板、agent 只能猜的那一刀。
  - 抽取能力：`withRetry` + `RetryOpts` 移出到新模块 `src/resilience/`，重写 3 处 import + 清理原模块 = **新建 1 模块 + 6 处**。
  - 改类型 `amountCents: number → Cents`：引入 1 个 branded 类型后按范围传播——`charge`=**3 处** / `charge+refund`（默认）=**5 处** / `all`=**8 处**。
  - 汇总（默认）：**4 个操作 → 20 处确切语义编辑 + 1 个新模块（另有 9 处调用点自动判定兼容、0 改动），触达 9 个文件（8 既有 + 1 新建），执行顺序确定（重命名→改类型→改签名→抽取），agent 待猜点数 = 0**；对照散文指令 = **4**。（`opts` 切必填时总数升到 29，直观显示这个决策的代价。）

## 10. 明确不做什么

- 不做登录 / 用户系统。
- 不接数据库 / 支付 / 外部私钥 / 真实 API / LLM。
- 不做生产级后端；不真正解析或改写用户的真实代码仓库（Demo 用固定 mock 图）。
- 不假造「AI 生成」步骤——所有展开都是可复现的确定性图遍历。
- 不做审计/闸门/校验/预检叙事——刻意聚焦「编排→展开→交付」的创作动线。

## 11. 成功体验标准

- 用户 3 分钟内能说出：**它解决什么**（人→agent 结构改动指令是散文、藏歧义、agent 只能猜）、**怎么用**（在符号图上编排语义操作 + 拍板歧义参数 → 实时看展开）、**增量在哪**（把「待猜点数」从 4 降到 0，产出可移植、机读的改动谱交付给任意 agent）。
- 切换操作/参数时，谱与收益指标即时、正确地重算。
- 首屏就能看懂「散文 vs 谱」的对照，且明显不是 Zero / IDE 重构 / 让 agent 直接吃散文的克隆。
