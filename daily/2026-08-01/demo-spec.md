# Demo 设计说明 — 2026-08-01

## 1. Demo 名称

**风洞 WindTunnel** — WASM agent 运行时「迁移前风洞」。

## 2. 一句话定位

把你 agent 的**真实工具负载**放进风洞，先算清它在进程内 WASM 运行时（如 agentOS）里**到底能不能跑、到底省多少**——用你的负载说话，而不是厂商头条的 254×。

## 3. 目标用户

运维/平台/基础设施工程师，以及 agent 平台的技术决策者：手里握着「要不要把 tool/code 执行层迁到进程内 WASM 运行时」这个决策的人。

## 4. 使用场景

看到 agentOS「冷启动 92×、内存 47×、成本 254×」的头条后，在**真正投入迁移工时之前**，用自己四类代表性负载之一（编码 / 数据分析 / 爬取 / 媒体处理）跑一遍风洞，得到**诚实倍数 + 兼容 X 光 + 逐项改造建议 + 出厂判定**，据此决定迁 / 谨慎迁 / 先改造 / 别迁。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 抽象 / CLI / API / 基础设施类产品（agent 执行运行时的采纳决策）
- 采用的演示方式：纯前端「**模拟体验 + 价值可视化**」——
  - **兼容 X 光表**（把抽象的「WASM 兼容性」可视化成每个工具的分层 + 原因）
  - **before / after 成本与延迟对比**（旧 microVM 基线 vs WASM 运行时）
  - **fallback 尖峰时间线**（把「静默掉进真沙箱」的冷启动尖峰画出来）
  - **阿姆达尔滑杆**（交互：拖动「重活占比」，看 254× 实时塌陷，讲清核心洞察）
- 演示的是**我们的创新切入点**（厂商中立、迁移前、用你的负载出诚实账），不是 agentOS 的克隆。

## 6. 核心流程（3 分钟内看懂价值）

1. 进入①「风洞台」→ 选一类代表性负载（编码 / 数据 / 爬取 / 媒体）。
2. 立即看到**兼容 X 光**（每个工具：native 便宜 / mount 按需真沙箱 / blocked 跑不了 + 原因）与**英雄数字**：厂商头条 **254×（划掉）** vs **你的真实倍数 N×**。
3. 切②「成本 × 延迟」→ 看 before/after 成本条（按分层堆叠）、冷启动 P99 对比、fallback 尖峰时间线——直观看到「省下来的钱被 fallback 尾巴吃掉」。
4. 切③「阿姆达尔滑杆 + 出厂判定」→ 拖滑杆「重活占比」，看 254× 实时塌成个位数；读**出厂判定**（迁 / 谨慎 / 先改造 / 别迁）+ 逐项**改造建议** + 诚实免责声明。

## 7. 页面结构（<= 3 个主要页面，Tab 切换）

- 页面 1 · **风洞台（兼容 X 光 + 英雄数字）**：负载选择器 + 工具分层表 + 254×划掉/真实倍数/native成本占比/fallback调用占比。
- 页面 2 · **成本 × 延迟（before/after）**：分层堆叠成本条、冷启动 P99 对比、fallback 尖峰时间线（SVG）、省钱/省延迟的诚实增量。
- 页面 3 · **阿姆达尔滑杆 + 出厂判定**：交互滑杆（重活占比→真实倍数实时塌陷 + SVG 曲线）、四色出厂判定卡、逐项改造建议、诚实免责声明。

## 8. 关键交互

- 负载切换（4 个预设）联动全站三屏数字。
- 阿姆达尔滑杆：0%→80% 重活占比，实时重算真实倍数并与固定的 254× 对照（核心「aha」）。
- 工具分层表的每个 tier 徽章 hover/展开显示「为什么是这个 tier」的原因（x86 二进制 / GPU / 原生 addon / WASI 不支持等）。

## 9. 使用的 mock 数据

全部为 mock，无真实运行时 / 外部 API / 后端。

- 4 个预设负载（`src/data/workloads.ts`）：每个含若干工具族 `{名称, 类别, 调用次数, 单位成本, tier, 原因}`。
- 成本/延迟模型常量（`src/logic/engine.ts`）：native 单位加速 S=254（取自报告头条）、mount 开销系数 1.2、blocked 开销系数 1.35、基线冷启动 850ms、native 冷启动 9ms、mount 冷启动 850ms（尖峰）。
- 引擎为一套**确定性可解释公式**（阿姆达尔式：真实成本 = native部分/254 + fallback部分×开销），非黑箱、非 LLM。所有数值已在构建前用独立脚本核验。

## 10. 明确不做什么

- 不做登录 / 用户系统。
- 不接数据库 / 支付 / 外部私钥 / 真实 API / 真实运行时。
- 不做生产级后端；不真的运行任何 agent 或采集真实 trace。
- 不谎称是精确报价——明确标注是**方法论演示 + mock 负载**。

## 11. 成功体验标准

- 用户 3 分钟内能说出：「它解决什么（迁移前用我的负载出诚实账）/ 怎么用（选负载→看 X 光→看成本→拖滑杆→读判定）/ 增量在哪（厂商中立、迁移前、敢说别迁；vs agentOS 卖引擎报喜、vs 观测工具事后看）」。
- 能亲眼看到「只要 5% 是重活，254× 就塌成个位数」的阿姆达尔洞察。
