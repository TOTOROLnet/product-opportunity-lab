# Demo 设计说明 — 2026-08-08

## 1. Demo 名称

对表 Duìbiǎo —— Agent 指令契约的「持续体检 / CI」

## 2. 一句话定位

把仓库里散落的 AGENTS.md / CLAUDE.md / Cursor rules / README / CI 当**可执行规格**，逐条对着仓库现实与 CI 真值判决 `对齐 / 漂移 / 冲突 / 无法验证`，给出契约健康分与一键对表修复——**给 agent 指令做 CI**。

## 3. 目标用户

重度使用 Cursor / Claude Code / Codex 的工程团队 lead 与开源维护者；他们已经在仓库里放了给 agent 看的说明，却没有任何机制保证这些说明还成立。

## 4. 使用场景

一支团队把包管理器从 pnpm 迁到 bun、改了端口、删了脚本、升了 Node 版本，但 AGENTS.md 仍写老命令、CLAUDE.md 说 npm、`.cursor/rules` 说 pnpm——三份指令互相矛盾。某个编码 Agent 随机挑一条照做，跑废一整轮才发现。对表在提交/CI 阶段就把这些「腐烂 + 冲突 + 无依据」的声明拦下来。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 抽象 / CLI / API / 基础设施类产品（agent 指令的 CI 校验层）
- 采用的演示方式：纯前端「**模拟体验 + 价值可视化**」，综合三种形式——
  - **网页版模拟终端回放**：脚本化重放「扫描仓库 → 抽取声明 → 对真值核对 → 跨文件对表」核心工作流；
  - **可展开账本（资源/结构视图）**：把每条被抽取的「声明」及其判决、证据、后果可视化；
  - **before / after 对比**：直观展示「不校验 → agent 照假命令翻车」与「对表后 → 收敛到单一真源」的增量价值。
- 演示的是**我们分析出的创新切入点**（把已有 agent 指令当可执行规格去校验并对表），不是 HAR（新契约编排）或 Reference（嵌入 doc-drift）的克隆。

## 6. 核心流程

（用户从进入到"看懂价值"的主路径，3 分钟内可完成）

1. **① 扫描台**：看到 mock 仓库 `acme/checkout-service` 及其散落的 5 份 agent 指令文件；点「运行契约扫描」，观看确定性模拟终端逐步回放（发现文件 → 抽取 N 条声明 → 对 CI 真值核对 → 跨文件冲突检测 → 输出健康分）。
2. **② 契约账本**：逐条查看被抽取的声明——状态徽章（对齐/漂移/冲突/无法验证）、来源文件、声明内容、仓库现实/CI 真值证据、严重度；展开任意一条可看「一个 agent 照此执行会怎样」的后果，以及可勾选「采纳对表修复」，健康分实时重算。
3. **③ 对表修复**：查看把 AGENTS.md/CLAUDE.md/rules 收敛到单一真源（CI + README 为真值）的修复 diff，健康分从 54 → 96，并对比「修复前 vs 修复后 agent 的一次典型执行」。

## 7. 页面结构（<= 3 个主要页面，采用顶部 Tab 切换）

- 页面 1（① 扫描台）：仓库卡片 + 指令文件列表 + 模拟终端回放。
- 页面 2（② 契约账本）：健康分与统计条 + 可搜索/可筛选的声明账本 + 逐条展开详情与修复勾选。
- 页面 3（③ 对表修复）：before/after 修复 diff + 健康分增量 + 「修复前/后 agent 执行」对比 + 可复制的契约体检报告文本。

## 8. 关键交互

- 「运行契约扫描」触发确定性终端回放动画（可重播）。
- 账本支持关键词搜索、「只看有问题」筛选、按行展开详情。
- 每条问题声明可勾选「采纳修复」，页面 2/3 的健康分与统计随所选修复实时联动（确定性重算，非随机）。
- 修复 diff 用「- 旧行 / + 新行」着色，直观展示对表结果。

## 9. 使用的 mock 数据

（全部为 mock，不接真实后端/外部 API/LLM）

- `src/data/scenario.ts`：mock 仓库元信息、5 份指令文件内容片段、仓库「现实真值」（packageManager=bun@1.1.30、bun.lockb、`.nvmrc`=20、CI 用 setup-bun + node 20/22、dev 端口 5173、`.env.example` 用 `STRIPE_SECRET_KEY`、无 `db:migrate` 脚本）、以及 12 条被抽取的「声明」（含来源、原始命令、判决、证据、严重度、后果、修复文本）。
- `src/logic/scan.ts`：确定性引擎——依据已采纳的修复集合，计算每条声明的有效状态、契约健康分（0–100）、分状态统计、before/after 执行叙事。
- 终端回放脚本：`scenario.scanLog`，固定行序与节奏。

## 10. 明确不做什么

- 不做登录 / 用户系统
- 不接数据库 / 支付 / 外部私钥 / 真实 API / 真实 LLM
- 不真的读取任何仓库、不执行任何真实命令（全部为 mock 判决）
- 不做生产级后端；不超过 3 个主要页面；全部数据 mock

## 11. 成功体验标准

- 用户 3 分钟内能说出「它解决什么问题（agent 指令悄悄腐烂/互相冲突）、怎么用（扫描→账本→对表修复）、增量在哪（可执行校验 + 跨文件冲突，而非新契约或嵌入相似度）」。
- 首屏即讲清「回放还原 agent，对表还原『指令是否还成立』」这一价值主张。
- 明确看出与 HAR / Reference 的本质区别（Demo 内含对比说明），不产生「这是照抄某产品」的观感。
