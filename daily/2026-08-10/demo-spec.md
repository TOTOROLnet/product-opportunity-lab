# Demo 设计说明 — 2026-08-10

## 1. Demo 名称

**预调 Pretune** — 本地后训练的「飞行前副驾」（Pre-Flight Copilot for Local Post-Training）

## 2. 一句话定位

在你敲下 `train` 之前，一层**厂商中立、透明可审计**的副驾：告诉你**该不该微调、这张卡塞不塞得下、该用哪种方法**。

## 3. 目标用户

有私有数据、只有游戏本/入门卡（4–12GB 显存或 Apple M 系）、想给 ≤8B 模型做后训练但**没把握**的独立开发者、小团队 ML 工程师、技术负责人。

## 4. 使用场景

用户在动手跑训练前，先在「飞行前副驾」里配置一次场景（任务意图 + 硬件 + 数据画像 + 基座模型），3 分钟内拿到：① 该不该调的判定与理由；② 逐层流式/量化后的显存预算与「塞得下吗」判定；③ 方法对号与一份可执行的训练计划。避免选错方法白跑、跑到中途 OOM、被黑箱自动化决定却无法审计。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ **抽象 / CLI / API / 基础设施类产品**（后训练决策 + 显存推理，无可视界面天然存在）
- 采用的演示方式：纯前端「**模拟体验 + 价值可视化**」——
  - **决策台**：确定性决策引擎，把「该不该调」的推理**显性化**（决策树结果 + 理由 + 「什么会改变结论」）。
  - **显存预算与逐层流式模拟**：`before/after 对比`（常驻 vs 逐层流式+NF4 的峰值显存条形图 + 逐层动画）+ `资源视图`（把抽象的显存占用可视化）+ fits/tight/OOM 判定。
  - **方法对号矩阵 + 训练计划**：把 23 种方法**家族**做成可比较矩阵，对号推荐并生成含 eval 派生/保存 gate/reward-hacking 观测点的计划卡。
- 演示的是**我们分析出的创新切入点**（训练之前、透明、厂商中立的决策+预算层），不是 Soup CLI（执行层/黑箱自动决策）的克隆。

## 6. 核心流程

（用户从进入到「看懂价值」的主路径，3 分钟内可完成）

1. 首屏即「飞行前副驾」：左侧配置区选 **任务意图 / 基座模型 / 硬件显存 / 数据画像**（都有预设，秒选）。
2. 切到 **① 决策台**：看引擎给出「该不该调」的判定卡（RAG-prompt / SFT-LoRA / 偏好对齐 / 蒸馏 之一）+ 三条理由 + 「什么情况下结论会变」；顺带看到「如果选错方法会怎样」的对照。
3. 切到 **② 显存预算**：看常驻 vs 逐层流式+NF4 的峰值显存条形对比 + 逐层流式动画 + 「你的卡塞得下吗」判定 + 时间↔显存交叉点说明（附「怎么算的」透明公式展开）。
4. 切到 **③ 方法与计划**：看方法家族对号矩阵（为什么是它、为什么不是其他）+ 一份可勾选的训练计划清单（数据预检→方法→量化→按规则的 lr/epoch→从你的数据派生 evals→保存前 gate→reward-hacking 观测）。
5. 改一个输入（如把显存从 12GB 调到 4GB，或把数据从「有偏好对）改成「只有少量标注」），实时看三屏结论如何变化——**即"副驾"价值的高光时刻**。

## 7. 页面结构（<= 3 个主要页面）

单页应用 + 顶部三个 Tab（共享左侧配置面板）：

- 页面/Tab 1：**决策台（该不该调）** — 判定卡 + 理由 + 结论敏感度 + 选错方法的代价对照。
- 页面/Tab 2：**显存预算（塞不塞得下）** — 常驻 vs 逐层流式 条形对比 + 逐层动画 + fits/tight/OOM + 透明公式。
- 页面/Tab 3：**方法与计划（怎么调）** — 方法家族对号矩阵 + 可执行训练计划卡。

## 8. 关键交互

- 左侧配置面板：任务意图（下拉/卡片）、基座模型（1B/3B/8B/14B）、硬件（4/8/12/24GB + Apple 选项）、数据画像（样本量档位、是否有偏好对、是否有标注、质量）。
- 每次配置变化 → 确定性引擎重算 → 三个 Tab 内容与结论**实时联动**。
- 显存 Tab：点击「逐层流式」触发一层层「加载→计算→释放」的动画，直观展示「峰值由一层界定，而非整模型」。
- 每处结论旁提供「怎么判断的 / 怎么算的」可展开说明，强调**透明可审计**（与黑箱自动化对立）。
- 全站显式标注：**显存为透明公式估算，非实测；不代表任何厂商的官方数字。**

## 9. 使用的 mock 数据

（全部为 mock / 公开近似架构常识，不接真实后端/外部 API）

- `data/tasks.ts`：任务意图列表（如「学我司客服语气」「抽发票字段成 JSON」「更礼貌地拒答」「领域问答」「把 14B 蒸成 3B」等），每个含它更偏向哪条决策路径的标签。
- `data/models.ts`：基座模型近似架构（参数量、层数、hidden size —— 标注为公开近似值），用于显存公式。
- `data/methods.ts`：方法家族（Prompt/RAG、SFT-LoRA、DPO、ORPO、SimPO、KTO、蒸馏）的适用条件、优缺点、显存/数据需求画像。
- 决策与显存公式：写在 `logic/engine.ts` 内，透明、可在 UI 展开查看。

## 10. 明确不做什么

- 不做登录 / 用户系统
- 不接数据库 / 支付 / 外部私钥 / 真实 API / LLM 调用
- 不做生产级后端；不真正跑训练、不读取真实 GPU
- 不冒充任何厂商实测数字；所有显存/性能均为透明估算并显式标注

## 11. 成功体验标准

- 用户 3 分钟内能说出：「它解决什么问题（动手前的决策+可行性）、怎么用（配一次看三屏）、增量在哪（透明、厂商中立、训练之前，vs Soup 的黑箱执行层）」。
- 改一个输入能立刻看到结论联动，感受到「副驾」而非「静态说明书」。
- 首屏不空白、无死链、核心三 Tab 均为已实现的真实交互而非空壳。
