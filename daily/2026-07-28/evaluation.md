# 自动体验 / 自测报告 — 2026-07-28

## 1. 构建结果
- `npm install`：成功（69 packages）。
- `npm run build`：成功（`tsc -b && vite build`，首轮通过，修复轮次：0/3）。产物 `dist/index.html` + 1 个 JS bundle（159KB / gzip 53KB）+ CSS。
- smoke 检查（`scripts/validate_demo.sh`）：通过（dist 首屏非空、含 `id="root"` 挂载节点、README 存在、有 JS bundle）。

## 2. 可用性检查
- `npm run preview -- --port 4173` 正常启动，`curl` 返回 200 且含 `id="root"`。
- 首屏非空白：Hero 讲清定位（「健康 AI 主动给建议 → 但对你一个人有没有用？」）+ 三 Tab 导航，浏览器实测渲染正常。

## 3. 核心流程是否闭合
闭合。浏览器实测走通完整主路径：
1. 实验设计台：点第 2 张建议卡（睡前补镁）→ 下方协议区正确更新（假设 / 主指标 / 基线-干预 / 建议天数 / 成败线 / 混杂因素）。
2. 读数：切「静息心率 / 深睡时长 / 主观精力自评」三个 pill → 图表、统计、结论卡随之切换。
3. 实验档案：汇总卡（1 有效 / 1 疑似安慰剂 / 1 数据不足）+ 表格，行内「看读数」可跳回。

## 4. 首屏是否讲清产品价值
讲清。Hero 一段话点明：健康 AI 已会主动给建议，但「对你一个人有没有用」没人解；验己坐在建议下游，把建议变成对照实验并给出**能识破安慰剂/均值回归/数据不足的诚实读数**，且「对大多数建议敢说没证据」。三个 chip 进一步强化差异化与边界（非医疗建议、全 mock）。

## 5. 交互是否有断点
无致命断点。三 Tab、建议卡选择、指标 pill 切换、before/after「并排对比」开关均可用；表格「看读数」跳转正常。图表柱子 hover 有 tooltip（第 N 天/期/数值）。响应式在窄屏降级为单列。

## 6. 是否只是概念包装（自嗨检测）
- 是否引用了报告中的具体信号：**是**。直接踩 2026-07-28 报告的 B 端信号（Illume Labs 纵向健康助手、报告自陈「差异化在多源融合+主动性能否被感知」）与 B-trend（健康 AI 护城河从「答得准」转为「持有纵向数据+主动提醒」），并对该趋势提出**独立推进判断**（下一层是「验证」而非「更多建议」）。
- 是否明确了创新切入点与增量价值：**是**。切入点＝建议的**验证层与诚实读数**；增量＝从「让你相信有用」转为「向你证明是否有用」，敢说「无效/数据不足」。
- 是否是某产品的照抄：**否**。Illume 是多源融合的主动建议助手（数据入口+推送）；验己不采集数据、不主打「越用越懂你」，而是建议下游的实验设计与诚实读数引擎，二者互补而非替代。三种诚实结论（有效/数据不足-均值回归/疑似安慰剂）是本产品的立身之本，非 Illume 功能的重排。
- 诚实性：读数引擎为**确定性统计替身**（非真实 AI 推断）、数据全 mock、明确「非医疗建议」——已在 Hero、footer、README、demo-spec、opportunity 多处如实标注，不夸大。

## 7. Demo 的最大问题
- 读数引擎是**确定性规则替身**，不是真实 AI/稳健统计；「个人证据强度」的权重系数为演示手调，真实产品需替换为经校准的贝叶斯/序贯检验方法。已如实标注，但用户需理解这是**价值可视化**而非成品算法。
- 数据为 3 场预置实验，无法自由输入自己的数据；用于讲清「机会与形态」足够，但不构成可用工具。

## 8. 是否建议用户人工体验
建议。核心「顿悟瞬间」在浏览器里很强：静息心率的「降了 2bpm 看似有效 → 其实落在噪声内且基线本就在下行（均值回归）」，以及冷水澡「第 1 周飙升 → 第 3 周回落（新奇效应）」，图表把「伪改善」可视化得很直观，值得亲自点一遍 before/after。

## 9. 下一步建议
- 把确定性读数替换为真实的序贯/贝叶斯 n-of-1 分析，并接入真实可穿戴/日志数据（隐私优先、端侧优先）。
- 支持用户自定义实验（自由文本建议 → LLM 生成协议）。
- 把「个人证据库」做成可长期积累、可对比人群基线的资产，强化留存与付费理由。
