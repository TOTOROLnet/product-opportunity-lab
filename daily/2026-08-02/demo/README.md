# 换挡 Downshift · 模型迁移的「按成功任务计价」离线复盘台

面对 **DeepSeek-V4-Flash** 这类「便宜三倍」的新模型，别看 `$/token` 单价、别信厂商榜单——
用你自己的 agent trace 重放，算清**每个成功任务**到底省不省钱、掉不掉成功率，再给可执行裁决。

> 核心命题：**单位 token 便宜 ≠ 单位任务便宜。**
> 真正决定成败的是 `每成功任务成本 = 每任务成本 ÷ 成功率`——它把「成本」和「能力（成功率/步数）」耦合进同一个数。

这是 product-opportunity-lab 2026-08-02 的当日 Demo，纯前端静态原型，**全部数值为 mock、方法论演示、非真实跑分**。

## 它解决什么

模型价格战每周都在打（DeepSeek / GLM / Kimi 轮流降价），"要不要换更便宜的模型" 是高频、直接烧钱的决策。
今天最常见的错误是**看单价拍板**（报告还在推「换个模型 ID 就享受成本红利」）。换挡的立场相反：

- **厂商话术**：`$/token` 输出单价 −87%！（虚荣指标）
- **诚实读数**：算上步数膨胀、真实缓存命中、成功率后的**每成功任务成本** —— 可能 −75%，也可能 **+35%（反而更贵）**。

## 三个页面

1. **换挡台**：厂商话术（划掉）vs 诚实每成功任务成本 + 大裁决卡（值得换 / 有条件换 / 先修再换 / 别换）+ 补救项 + 月度体量估算。
2. **逐项复盘**：把「每任务成本（更便宜）」到「每成功任务成本（未必便宜）」的翻转逐行拆开 + 输入/输出堆叠柱 + vanity vs honest 对比。
3. **盈亏平衡**：拖动「B 成功率 / B 步数膨胀」两个滑杆，实时看诚实成本比 r、裁决翻转、成本比曲线与盈亏平衡成功率线。

4 个 mock 工作负载覆盖 4 档裁决：编码 PR 车队（值得换）/ 长上下文文档 QA（有条件换）/ 工具编排客服（先修再换）/ 实时语音 agent（别换，表面 −25% 实际 +35%）。

## 技术栈

- Vite + React + TypeScript
- `vite.config.ts` 设 `base: './'`，保证部署到任意 GitHub Pages 子目录（`/<date>/`）都能正确加载资源。
- 确定性成本/裁决引擎在 `src/logic/engine.ts`（纯函数：`effInput / costPerTask / analyze / analyzeWith / classifyVerdict / breakEvenSuccess`）。
- mock 数据在 `src/data/workloads.ts`，引擎数值已用一次性脚本预校验。

## 明确不做

- 不做登录 / 用户系统；不接数据库 / 支付 / 外部私钥 / 真实 API / **真实模型调用**；不做生产级后端。
- 不声称数值为真实跑分——首屏与页脚均标注「方法论演示 · 数值为 mock」。真实使用时把「B 的成功率/步数」换成你自己 trace 的重放实测。

## 为什么不是照抄

- 不是 **DeepSeek** 的克隆：DeepSeek 是被评估的**对象（一个模型，报喜）**；换挡是评估「值不值得换」的**买方决策工具**，指标相反（$/token vs $/成功任务），自身不训练、不托管任何模型。
- 不是 08-01 **风洞 WindTunnel** 的重复：风洞评估**执行运行时（WASM 沙箱）**、算成本倍率、**完全不碰成功率**；换挡评估**模型**、算每成功任务成本 + 成功率变化，核心是「价格×能力耦合」——对象、指标、暴露的失败模式都不同。
