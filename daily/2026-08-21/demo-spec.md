# Demo 设计说明 — 2026-08-21

## 1. Demo 名称
留痕 Liúhén — Agent 上下文压缩(compaction)的「折叠差异 + 保命清单」审计台

## 2. 一句话定位
长程 Agent 中途会把长会话静默压缩成摘要；留痕把「这一次压缩到底扔了什么、风险多大」变成可读的折叠差异，并让你钉住关键条目（保命清单），再回放证明「钉住它就不会跑偏」。

## 3. 目标用户
跑长程（数十至上百步）Agent 的开发者、Agent 平台/框架团队，以及做 Agent/API 的模型厂商侧团队。

## 4. 使用场景
一条真实的编码 Agent 长任务（「把支付模块迁移到新 SDK，且绝不改动对外 public API 签名」）跑了几十步，中途触发上下文压缩。默认压缩把「绝不改动 public API 签名」这条硬约束折叠丢弃，Agent 在第 18 步改了签名 → 契约测试全红、用户拒收、整段返工。留痕让你看见这次折叠丢了什么、为什么高风险，钉住它后回放：Agent 保住签名，任务通过。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 抽象 / CLI / API / 基础设施类产品（上下文/压缩机制，不可直接肉眼可见）
- 采用的演示方式：纯前端「**模拟体验 + 价值可视化**」——
  - **折叠差异视图（before / after）**：压缩前窗口 vs 压缩后摘要，逐条分类 + 风险标注；
  - **保命清单（可交互控制面）**：勾选/钉住条目，实时重算「本次压缩会保留/丢弃什么」与风险分；
  - **回放对比（before-after 价值可视化）**：默认压缩 vs 带保命清单，两条轨迹并排，标出跑偏点与最终结局（失败/通过）、token 账单。
- 演示的是**我们分析出的创新切入点**（买方侧、厂商中立的压缩审计 + 控制面），不是 Grok 4.6（产出压缩的模型）的克隆，也不是通用 trace 看板。

## 6. 核心流程
（用户从进入到「看懂价值」的主路径，3 分钟内可完成）
1. 进入「原理」标签：30 秒读懂「压缩是什么、为什么静默丢弃会让 Agent 跑偏、留痕做了什么不同」。
2. 切到「折叠台」：看一条长轨迹时间线上标出的压缩事件与跑偏点；点开压缩事件，看到 before/after 折叠差异，被丢弃的「绝不改动 public API 签名」被标为**高风险丢弃**。
3. 在右侧「保命清单」勾选钉住这条约束 → 折叠差异实时更新（它从「丢弃」变为「强制保留」），风险分下降。
4. 切到「回放」：并排对比「默认压缩」（第 18 步跑偏→任务失败）与「带保命清单」（保住签名→任务通过），看到 token 账单与「避免的返工」。

## 7. 页面结构（<= 3 个主要页面）
单页应用 + 3 个标签区（与实验室既有结构一致，构建稳定）：
- 区 1「原理 How」：价值主张 + 压缩失败模式讲解 + 分类法(taxonomy) + 明确「不是什么」。
- 区 2「折叠台 Fold Desk」：左=轨迹时间线（压缩标记 + 跑偏标记）；中=选中压缩事件的 before/after 折叠差异（保留/有损/丢弃三态 + 风险徽章）；右=保命清单（可勾选钉住，实时重算）。
- 区 3「回放 Replay」：默认 vs 带保命清单 的两条轨迹并排回放 + 结局 + token/返工账单。

## 8. 关键交互
- 时间线点选压缩事件 → 中栏折叠差异随之切换。
- 保命清单勾选/取消 → 折叠差异条目三态与风险分实时联动（确定性重算）。
- 回放区「▶ 播放」按钮 → 两条轨迹逐步推进，跑偏步高亮，结局与账单在末尾结算。
- 全程无网络请求、无输入框提交到后端，纯本地状态。

## 9. 使用的 mock 数据
（全部为 mock，不接真实后端/外部 API）
- 一条 mock 编码 Agent 轨迹：约 24 步，含目标、约束、若干工具调用与 2 次压缩事件（`src/data/trajectory.ts`）。
- 上下文条目 items：带 `type`（user_constraint / decision / file_ref / error_learned / todo / chatter）、`tokens`（估算）、`riskWeight`（丢弃风险权重）、`causesDriftAtStep`（若被丢是否触发某步跑偏）。
- 确定性引擎 `src/engine.ts`：输入(轨迹 + 保命清单集合) → 输出(每次压缩的保留/有损/丢弃分组、风险分、token 节省、是否触发已知跑偏、最终结局)。无随机、可解释。

## 10. 明确不做什么
- 不做登录 / 用户系统。
- 不接数据库 / 支付 / 外部私钥 / 真实 API / 真实模型推理。
- 不做生产级后端、不真正压缩真实上下文（Demo 用脚本化 mock 轨迹演示机制）。
- 不做通用 trace/token 大看板（只聚焦「压缩这一步」的审计与控制）。

## 11. 成功体验标准
- 用户 3 分钟内能说出：「它解决什么问题（压缩静默丢约束→Agent 跑偏）、怎么用（看折叠差异 + 钉保命清单）、增量在哪（默认 vs 带清单的回放：一次跑偏与整段返工被避免）」。
- 首屏（原理区）不空白、能自证价值；折叠台与回放的交互闭环、无断点。
- 用户能明确感知这是**买方侧、厂商中立的压缩审计 + 控制面**，而非模型或通用看板的克隆。
