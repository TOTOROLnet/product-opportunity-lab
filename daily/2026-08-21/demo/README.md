# 留痕 Liúhén — Agent 上下文压缩(compaction)的「折叠差异 + 保命清单」审计台

> 2026-08-21 每日机会 Demo · 纯前端静态原型（Vite + React + TypeScript）

## 这是什么

长程 Agent 跑到一半，上下文会膨胀。为了降本提速，模型 / harness 会把长会话**静默压缩**成一段摘要——这一步默默替你决定了「什么留、什么扔」。扔错一条**硬约束**或**已定决策**，Agent 会在几十步后「忘了自己答应过什么」而跑偏，代价是**整段返工**。

**留痕**站在压缩这一步**之上**（买方侧、厂商中立），把每一次压缩变成可读的：

- **折叠差异（before / after）**：压缩前窗口 vs 压缩后摘要，逐条给出「保留 / 有损压缩 / 丢弃」+ 风险标注；
- **保命清单（pin）**：一个**控制**动作——规定哪些条目压缩时必须保留，绝不静默丢弃；
- **回放对比**：默认压缩 vs 带保命清单，两条轨迹并排，标出跑偏在第几步引爆、最终结局（失败/通过）与 token 账单。

## 页面（单页 + 3 个标签区）

1. **① 原理**：压缩为何让 Agent 跑偏、留痕做了什么不同、条目风险分类法、诚实边界（「不是什么」）。
2. **② 折叠台**：左=轨迹时间线（点选压缩事件）；中=该次压缩的折叠差异 before/after；右=保命清单（勾选钉住，实时重算风险分与省下 token）。
3. **③ 回放**：默认压缩 vs 带保命清单 的两条轨迹逐步回放 + 价值账单结算。

> 建议路径：原理 →（折叠台）看压缩 #1 丢了「绝不改 public API 签名」→ 点「一键钉住风险项」→（回放）▶ 播放，看结局从 ❌ 翻成 ✅。

## 技术说明

- **技术栈**：Vite + React + TypeScript，无第三方 UI 库（手写 CSS）。
- **`vite.config.ts` 设 `base: './'`**：相对路径，保证部署到任意 GitHub Pages 子目录（`/<date>/`）都能正确加载资源。
- **确定性 mock 引擎**（`src/engine.ts`）：输入(轨迹 + 保命清单) → 输出(每次压缩的折叠差异 / 风险分 / token 账单 / 跑偏回放 / 结局)，无随机、可解释。
- 场景与数据均为虚构（`src/data/trajectory.ts`）。

## 明确不做

不接后端 / LLM / 真实上下文 / 数据库 / 支付 / 密钥 / 登录 / 外部 API；不做用户系统；不真正压缩真实上下文（用脚本化 mock 轨迹演示机制）；不做通用 trace/token 大看板。

## 边界与非克隆声明

演示的是**买方侧、厂商中立的「压缩审计 + 控制面」创新切入点**：

- 不是 **Grok 4.6** 那样**产出**压缩的模型；留痕站在其上、替使用方审计与控制压缩。
- 不是通用 LLM 可观测性（Langfuse/Helicone 类）——只聚焦「压缩这一步」的 before/after 差异 + 风险标注 + 保命清单**控制**。
- 不是「记忆库回忆信任闸」——针对的是单次长运行内、压缩折叠掉了什么，而非在回忆持久记忆时打分。
