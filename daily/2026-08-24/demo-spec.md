# Demo 设计说明 — 2026-08-24

## 1. Demo 名称
召算 Zhàosuàn — 「AI 员工」运行时成本 × 毛利推演沙盘

## 2. 一句话定位
在你给 AI agent 配「电脑」、给产品定价之前，把四种运行时架构下的月账单、毛利随规模的悬崖、以及「隔离/可靠/单位成本」不可能三角，一次性算清楚、看明白。

## 3. 目标用户
正在/即将上线「AI 员工 / computer-use agent」的 solo founder、小团队 infra/平台决策人；以及预研多租户 sandbox 计费模型的平台团队。

## 4. 使用场景
你打算做一个「AI 员工」产品，定价 $9/月。你的用户里有一批「来了不回」的重度用户，任务时长长、闲置比高。你不知道该像 AutoClaw 走本地、像 Epho 走云端常驻、还是像 Construct 走边缘按需——也不知道到多少用户时哪种架构会把你的毛利拖到负。你把画像和定价输进召算，一眼看清甜点在哪、悬崖在哪。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 抽象 / CLI / API / 基础设施类产品（agent 运行时成本决策）
- 采用的演示方式：纯前端「**模拟体验 + 价值可视化**」——
  - **可调参数沙盘**（滑块驱动确定性成本模型）
  - **毛利 × 压力维度曲线**（SVG 折线图，可切换 闲置比 / 鲸鱼放大 / 用户规模，标出各架构「毛利转负」点）
  - **不可能三角雷达**（隔离/可靠/单位成本三轴对比四架构）
  - **before / after 架构对比**（一键切换画像/架构，看甜点漂移）+ 脚本化「顾问解读」
- 演示的是**我们分析出的创新切入点**（上线前、厂商中立的架构×定价决策沙盘），**不是** Construct 运行时的克隆。

## 6. 核心流程
（用户从进入到「看懂价值」的主路径，3 分钟内可完成）
1. 进入**沙盘**页：看到默认画像（一个平价订阅的 AI 员工产品）与四架构的即时成本/毛利卡片，最优架构被高亮为「甜点」。
2. 拖动滑块（如把「闲置比」从 30% 拉到 70%、把「鲸鱼比例」拉高），实时看到云端常驻的毛利率崩塌、边缘按需保持健康——直观感受「成本拖垮」。
3. 看**毛利×压力维度曲线**：切到「闲置比」轴，找到云端常驻的毛利转负点；再切「鲸鱼放大」「用户规模」轴，发现毛利率对用户数几乎不敏感（破除「长大自动盈利」错觉）。
4. 切到**架构对比**页：三种真实世界路线（本地/云端常驻/边缘按需，对应 AutoClaw/Epho/Construct 的路子）并排 before/after，读一段自然语言「顾问解读」给出甜点建议与理由。
5.（可选）切到**方法论**页：看成本模型公式与「报告事实 vs 我的建模假设」透明声明。

## 7. 页面结构（<= 3 个主要页面）
- 页面 1：**沙盘（Sandbox）**——左侧画像滑块 + 定价；右侧四架构成本/毛利卡片（高亮甜点）、毛利×压力维度曲线（可切轴）、不可能三角雷达；顶部 3 个一键场景剧本预设。
- 页面 2：**架构对比（Before/After）**——本地 / 云端常驻 / 边缘按需 三路并排，成本/毛利/冷启动/隔离风险对照 + 脚本化「顾问解读」自然语言诊断。
- 页面 3：**方法论 & 透明度（Method）**——成本模型公式、各架构计费假设、报告事实 vs 我的建模假设声明、免责说明。

## 8. 关键交互
- 滑块与预设：MAU、每日任务/人、平均任务时长、闲置比、并发峰值倍数、鲸鱼比例与放大倍数、定价（$/月）；所有输出实时重算。
- 甜点高亮：按**风险调整推荐分（毛利率 − 运维/风险惩罚项）**在「能交付自治」的架构里选最高者并高亮；本地客户端因不满足「离开时继续干活」展示但不入选甜点。
- 转负点标注：沿所选压力维度（闲置比 / 鲸鱼放大 / 用户规模）自动标出各架构毛利首次转负的位置。
- 顾问解读：根据当前数值从模板生成一段中文自然语言诊断（明确标注为脚本化模拟，非真实 LLM 调用）。

## 9. 使用的 mock 数据
（说明数据来源与结构，全部为 mock，不接真实后端/外部 API）
- **架构参数表**（`src/data/architectures.ts`）：四种架构的单位成本假设、闲置计费方式、冷启动量级、隔离/可靠性评级——数值为我基于常识设定的**建模假设**（非真实云报价），在方法论页显式声明。
- **场景剧本**（`src/data/scenarios.ts`）：3 个预设画像（低频重任务法务助理 / 高并发轻任务客服 agent / 长时后台 research agent）。
- **成本模型**（`src/lib/costModel.ts`）：确定性公式，输入画像+定价→输出各架构月成本、毛利、随规模曲线、三难评分。
- 报告事实（Construct/AutoClaw/Epho/三难/成本拖垮）作为**参考语境**引用，均标注来源为 2026-08-24 radar 报告。

## 10. 明确不做什么
- 不做登录 / 用户系统
- 不接数据库 / 支付 / 外部私钥 / 真实 API / LLM
- 不做生产级后端，不真正运行任何 agent、不真正开任何云机器
- 不声称成本数字为真实云报价（明确标注为建模假设）

## 11. 成功体验标准
- 用户 3 分钟内能说出：「它帮我在上线前比较 agent 运行时架构与定价、看清各架构在什么规模会把毛利拖到负、给出甜点建议」。
- 能亲手拖动滑块复现「成本拖垮」（闲置/鲸鱼拉高→云端常驻毛利崩塌），并理解不可能三角的权衡。
- 能说清它**不是** Construct 的克隆：召算是决策沙盘、厂商中立、不跑 agent。
