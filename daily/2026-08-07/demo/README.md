# 归位 Guīwèi — 长任务 Agent 复跑前的「世界重校安检台」

> 在长任务 Agent 按 append-only 日志「原地续跑」之前，先把它记得的世界(T0) 与现在的世界(T1) 逐条对齐、算漂移、裁决该不该续。
> **回放还原 Agent，归位还原「续跑是否安全」。**

本目录是 `product-opportunity-lab` 2026-08-07 当日的纯前端静态 Demo（Vite + React + TypeScript）。

## 它解决什么

今日报告 A 类头号信号 **Muse Code**（Meta，17/18）用 append-only 事件日志实现「回放级精确」的崩溃恢复——崩溃 20 小时也能原地续跑。但这里藏着一个被忽视的前提：**日志能忠实还原 Agent 的内部状态，却无法还原外部世界。** 18 小时里，别人可能合并了它依赖的 PR、oncall 打开了 config flag、另一个流程已应用了它「记得还没应用」的 DB migration、它的目标工单已被关成 won't-fix。此时盲目续跑 = 重复动作 / 覆盖他人改动 / 数据损坏 / 追一个已死的目标。

「归位」坐在复跑动作的**上游**，是一层厂商中立、只读、前向的安检：抽出 Agent 复跑会依赖的每条「世界假设」，对活世界探测后判定 `一致 / 漂移 / 已失效`，再给出复跑裁决（`自动续 / 重规划 / 人工确认 / 跳过 / 中止`）。

## 三个视图（3 分钟看懂）

1. **复跑总览**：暂停中的长任务卡片（27/42、缺口 18h22m），以及两个入口——「直接按日志复跑」vs「先过归位安检」。
2. **世界重校**（核心）：假设账本，逐条 T0 vs T1 对照 + 证据下钻；勾选「反事实：假装这条其实没变」可让确定性引擎**实时重算**裁决；下方是逐步复跑计划。
3. **复跑简报**：朴素回放 vs 归位安检后复跑的 before/after 事故对比、指标条、可交接的文本简报。

```bash
npm run preview  # 预览已 build 的产物
```

## 关键实现说明

- `vite.config.ts` 设 `base: './'`（相对路径），保证部署到任意 GitHub Pages 子目录（`/<date>/`）都能正确加载资源。
- 确定性引擎在 `src/logic/reconcile.ts`：比较 T0 记得值与（可被反事实覆盖的）T1 生效值→判级→映射裁决→汇总步骤计划与 before/after 影响。逻辑而非写死文案，反事实开关会触发全量重算。
- Mock 场景在 `src/data/scenario.ts`（7 类真实漂移：repo HEAD 前移 / PR 被他人合并 / config flag 被改 / CI 转红 / migration 已应用 / 依赖未变(对照一致) / 目标工单被关）。

## 边界（明确不做）

- 纯前端静态站点：**不接**后端 / 数据库 / 支付 / 登录 / LLM / 外部 API。
- 不真的读取任何 Git/CI/DB/工单，所有 T0/T1 世界快照均为 mock，界面内已标注「模拟」。
- 演示的是「复跑前世界重校」这一创新切入点，与 Muse Code（恢复引擎，目标是无缝续）目标函数相反，非照抄。
