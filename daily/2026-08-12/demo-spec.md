# Demo 设计说明 — 2026-08-12

## 1. Demo 名称

**随读 Suídú** — 自主 Agent 长时运行后的"3 分钟补看"阅读器。

## 2. 一句话定位

把一段过夜/后台自治 agent 的整趟运行（含它给项目改了什么、给自己改了什么），重构成一条 3 分钟能读懂的叙事时间线，并只把需要你拿主意的 2–3 个岔口顶出来——不打分、不放行、不判对错。

## 3. 目标用户

把任务委派给自治/后台/过夜 coding agent（Cursor 后台 agent / Claude Code / Devin 式）的开发者与 Tech Lead。他们的处境：一觉醒来 / 一个会开完，面对一堆"已经发生、但自己没在场看"的变更，要么盲信合并（失控），要么逐行爬日志（昂贵）。

## 4. 使用场景

你昨晚把「给后台管理页加 CSV 导出，并顺手修掉相关的 flaky 测试」这个任务丢给了一个自治 agent。它跑了约 4 小时、41 步、动了 9 个文件、拐过 2 次弯、替你做了 3 个假设、留了 2 个悬案，还按 Continual Harness 给自己改了 2 处（新增/更新了 skill 与 memory）。早上你打开随读，3 分钟补看懂全过程，只需针对被顶出来的 3 个岔口拿主意。

## 5. Demo 策略分型（重要）

- 本机会属于：**■ 抽象 / Agent 运行时 / 基础设施类产品**（对象是"一段 agent 运行"，不是一个可直接点的可视界面）。
- 采用的演示方式：纯前端 **"模拟体验 + 价值可视化"**——
  - **模拟运行回放**：内置一段脚本化的 mock agent 运行轨迹（章节 / diff / 工具调用 / 假设 / 悬案 / 自我修订 / 原始日志全部 mock）。
  - **叙事时间线**（把抽象的运行结构可视化为可滚动、可展开的章节）。
  - **before / after 对比**（原始 41 步日志 + 9 文件 diff vs 3 分钟叙事，用"补看用时"把增量做到可感）。
- 演示的是**我们分析出的创新切入点**（把自治运行重构成"给人补看的叙事 + 只盯这些"），**不是 Prime Agent 的克隆**（我们不造 harness、不让 agent 自改，只服务其下游的人类理解）。
- **诚实标注**：页面显式说明这是 mock 预置轨迹与叙事，非在线推理。

## 6. 核心流程（用户 3 分钟内从进入到"看懂价值"）

1. 进入 **① 补看** 首页：顶部一行看到本趟目标 + 一句话战报（41 步 / 9 文件 / 3 假设 / 2 悬案 / 2 自我修订 / 估算逐行爬 ~17 分钟 vs 随读 ~3 分钟）；右栏「只盯这些」已把 3 个该你拿主意的岔口顶到最上。
2. 沿叙事时间线**逐章下滑**：每章一句"发生了什么 & 为什么"，点开看真实 diff/工具调用；读到织入的**假设卡**（点开看"它凭哪一步这么假设"）与**悬案卡**。
3. 打开顶部 **「只看需要我决定的」** 开关：时间线瞬间收起为只剩假设/悬案/自我修订三类，验证"3 分钟只盯该盯的"。
4. 进 **② 它改了自己**：读一份"这趟给自己改了什么"的可读变更日志（Prime Agent 亮点），每条附触发它的轨迹证据 + "这会如何改变它下次的行为"。
5. 进 **③ 对照**：左看原始 41 行工具日志 + 9 文件 diff（人要爬 ~17 分钟、易漏假设），右看随读的 3 分钟叙事——增量一目了然。

## 7. 页面结构（<= 3 个主要页面）

- **页面 1 · 补看（首页 · 核心）**：叙事时间线（分章卡片，可展开 diff/工具调用）+ 织入的假设卡/悬案卡 + 右栏「只盯这些」+ 顶部「只看需要我决定的」过滤开关 + 一句话战报条。
- **页面 2 · 它改了自己（Self-edits）**：Continual Harness 式自我修订的可读变更日志（skill/memory 的 add/update，含 before/after 与触发证据、对未来行为的影响），非判决式——只"看懂 + 可标记'下次留意'"。
- **页面 3 · 对照（Before/After 价值可视化）**：左原始日志+diff 墙 / 右随读叙事的分屏；"读懂用时"对比条（~17 分钟 → ~3 分钟）；可展开原始日志以证明叙事有据、未藏信息。

## 8. 关键交互

- 章节卡展开/收起真实 diff 与工具调用。
- 点击假设卡 → 高亮/跳转到触发该假设的那一步（可追溯性 = 信任）。
- 顶部「只看需要我决定的」开关 → 过滤为仅 假设 / 悬案 / 自我修订。
- 右栏「只盯这些」条目 → 点击滚动定位到时间线中对应章节/卡片。
- 页 3「读懂用时」对比条 + 「展开原始日志」以自证不藏信息。
- 全局提示条：明示 mock 预置轨迹、非在线推理。

## 9. 使用的 mock 数据

全部为 mock、不接真实后端/外部 API。核心数据结构（`src/data/run.ts` + `src/types.ts`）：

- `AgentRun`：`{ goal, startedAt, durationMin, steps, filesChanged, linesChanged, chapters[], assumptions[], looseEnds[], selfEdits[], rawLog[] }`。
- `Chapter`：`{ id, phase(确认目标/首次尝试/遇阻转向/收敛/自我修订/收尾), title, oneLiner, why, tools[], touchedFiles[], durationMin, diff?, relatedAssumptionIds[], relatedSelfEditIds[] }`。
- `Assumption`：`{ id, text, divergence(用户可能不同意的程度 0–3), evidenceStepRef, chapterId }`。
- `LooseEnd`：`{ id, text, severity, chapterId }`。
- `SelfEdit`：`{ id, kind(skill/memory/subagent), op(add/update), name, before?, after, evidence, futureImpact }`。
- `rawLog`：一段 41 行的 mock 原始工具日志（供页 3 的 before 墙 & 可追溯展开）。
- 场景：CSV 导出 + 修 flaky 测试的一趟自治运行。数字（步数/文件/用时估算）在 `logic/engine.ts` 由纯函数从数据推导，且用 `_verify.ts` 预校验。

## 10. 明确不做什么

- 不做登录 / 用户系统。
- 不接数据库 / 支付 / 外部私钥 / 真实 API / 真实 agent 运行时。
- 不做生产级后端；不做在线 LLM 推理（叙事为 mock 预置）。
- 不打分 / 不放行 / 不判"对错"——随读只帮人读懂，价值不是一个 verdict/score。
- 不超过 3 个主要页面。

## 11. 成功体验标准

- 用户 3 分钟内能说出："它解决什么问题（长时自治运行后的补看理解）、怎么用（读叙事时间线 + 只盯这些 + 它改了自己）、增量在哪（vs 逐行爬日志 / vs 会话摘要 / vs eval）"。
- 首屏即让人感到"我不用逐行爬日志也能接手这趟运行"，并能立刻指出该他拿主意的 2–3 处。
- 全程能一键从叙事展开到它所依据的原始步骤/diff（可追溯，不是玄学总结）。
