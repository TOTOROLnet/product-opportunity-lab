# Demo 设计说明 — 2026-07-29

## 1. Demo 名称
准星 Zhǔnxīng —— 运行时 LLM 判官的"归零校准台"

## 2. 一句话定位
在把 LLM-as-judge 接到运行时"拦/批/杀"开关之前，先用你自己的真实争议案例给它**归零**：量出它的**误杀率**与**漏放率**、看清"每拦下 1 个坏动作要误伤多少正常业务"，再决定阈值与是否敢让它开火。

## 3. 目标用户
正在（或即将）把评估 / LLM-as-judge 接到运行时 block/kill 的 agent 平台与团队——他们已经或即将让一个判官拥有拦截真实业务动作的权力，却没有工具量化它的误杀 vs 漏放取舍。

## 4. 使用场景
团队准备给 agent 上线一个"评估越线就拦/杀"的 guardrail（如 Prefactor 那套）。上线前把过去被拦/被放的真实争议 run 攒成一份带**人类专家真值**的黄金集，导入准星 → 拨动阈值看**混淆矩阵**与**代价曲线** → 钻取判官与人类分歧的案例、定位**失败模式**（关键词过度触发 / 注入漏判）并打补丁 → 得到"出厂判定"：这个判官在哪个阈值能开火、要付多少误伤、还漏不漏危险动作。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 抽象 / 基础设施类产品（元评估 / 校准台）——用纯前端"**模拟体验 + 价值可视化**"呈现。
- 采用的演示方式：
  - **可搜索/可钻取面板 + 资源视图 + before/after 对比**的组合。核心是把"判官到底准不准"这件抽象事，用**混淆矩阵 + 代价曲线 + 分歧案例卡**可视化出来。
  - 因为"真实判官打分"不能实时调用模型，改用**预置 mock 黄金集（真实感的争议 run + 人类真值 + 判官打分）+ 确定性统计引擎**做模拟体验（对引擎如实标注："确定性统计替身，非真实模型推断"）。
  - 关键价值瞬间用 **before / after 对比**呈现：**默认拍脑袋阈值 70（误杀 20% 且仍漏放 3 个危险动作，总代价 340）** vs **准星校准后（阈值校准到 60 + 打两个失败模式补丁 → 误杀 10%、漏放归零，总代价 10）**。
- 演示的是我们分析出的创新切入点——**给判官归零的元评估/校准层**，不是 Prefactor（评估驱动的运行时执行平台）的克隆；准星不下达任何 block/kill，只回答"判官能不能开火"。

## 6. 核心流程（3 分钟内看懂价值）
1. 首屏读到定位与"**评估驱动执行 → 那谁来评估评估者？**"的价值主张，看到一份 mock 黄金集（十余条真实感争议 run，每条含 agent 动作 / 人类专家真值 / 判官风险分）与当前判官的"出厂默认阈值 70"的糟糕成绩单。
2. 进入**校准台**：拖动阈值滑杆 → 混淆矩阵（命中拦截 / **误杀** / **漏放** / 正常放行）与误杀率、漏放率实时刷新；旁边代价曲线随阈值移动，标出"最小代价阈值"和"零漏放的最低误杀点"。
3. 切到**分歧**：只看判官与人类不一致的案例，逐条展开——agent 动作、判官打分与理由、人类真值、并标注**失败模式**（关键词过度触发 / 注入漏判 / 校准正常）；打开"失败模式补丁"开关（去关键词偏置 / 加注入识别），看这些案例的判官分被确定性修正、混淆矩阵随之改善。
4. 切到**出厂判定**：并排给出**朴素上线（默认阈值、不校准）vs 准星校准后**的两张成绩单 + 一句诚实结论（"在你选的这个点，你仍会误伤 X% 正常业务——可接受吗？"）+ 免责声明（mock 数据、确定性替身、非医疗/非法律/非真实模型推断）。

## 7. 页面结构（<= 3 个主要页面，用顶部 Tab 切换）
- 页面 1 · 校准台（Calibrate）：阈值滑杆 + 实时混淆矩阵（2×2）+ 误杀率/漏放率/精确率/召回率 + 代价曲线（阈值→总代价，标注最小代价点与零漏放点）。这是主舞台。
- 页面 2 · 分歧（Disagreements）：只列"判官≠人类"的案例卡，逐条展开动作/判官理由/人类真值/失败模式标签；顶部两个"失败模式补丁"开关，切换后案例分与页面 1 矩阵联动更新。
- 页面 3 · 出厂判定（Verdict）：朴素 vs 校准后 before/after 成绩单 + 推荐操作点 + 诚实结论句 + 免责声明。

## 8. 关键交互
- 阈值滑杆（0–100）：拖动即时重算混淆矩阵、四项率、代价，并在代价曲线上移动当前点。
- 失败模式补丁开关（2 个）：`去关键词偏置`（对"退款/refund"类误触发案例下调判官分）、`加注入识别`（对 prompt 注入改写型漏判案例上调判官分）；开启后确定性修正受影响案例的判官分，页面 1/2/3 全部联动。
- 分歧案例卡点击展开：显示完整动作描述、判官分与理由、人类真值与理由、失败模式标签、该案例在当前阈值下属于误杀/漏放/命中/正常。
- 一键"应用准星推荐"：把阈值设到推荐点 + 打开两个补丁，直接跳到出厂判定看 after 成绩单。
- 全程无网络请求、无登录、无真实模型调用、无输入真实数据。

## 9. 使用的 mock 数据（全部为 mock，不接真实后端 / 外部 API）
一份预置**黄金集**：15 条争议 agent run（贴近报告里 Conduit/Prefactor 语境：退款、改单、派工、发货、访问敏感数据、外部转账等）。每条字段：
- `id`、`action`（agent 想执行的动作，人话）、`context`（一句话背景）
- `humanVerdict`：`ALLOW`（正常业务，应放行）/ `BLOCK`（危险，应拦）——人类专家真值
- `severity`：BLOCK 类的危险等级（用于代价加权）
- `judgeScore`：0–100 判官风险分（>= 阈值即判官拦截）
- `judgeReason`：判官给分理由（一句话）
- `failurePattern`：`keyword-overtrigger`（判官因关键词误判高危）/ `injection-miss`（判官漏判注入改写）/ `calibrated`（判官判得对）
- `patchDelta`：补丁开启后对该案例 `judgeScore` 的确定性修正量

读数引擎（`src/logic/engine.ts`）确定性计算：给定阈值 T 与补丁开关，
- 逐案例：`effectiveScore = judgeScore + Σ 已启用补丁的 patchDelta`；`judgeBlocks = effectiveScore >= T`
- 混淆矩阵：TP=命中拦截（BLOCK∧block）、FP=**误杀**（ALLOW∧block）、FN=**漏放**（BLOCK∧allow）、TN=正常放行（ALLOW∧allow）
- 率：误杀率=FP/(所有 ALLOW)、漏放率=FN/(所有 BLOCK)、精确率、召回率
- 代价：`cost = FP·costFalseKill + Σ_FN severity·costFalsePass`（漏放按危险等级加权，代价远高于误杀）
- 扫描 T=0..100 生成代价曲线，找最小代价阈值、零漏放的最低误杀阈值
故事线（预置数值保证成立）：15 条中 10 条 ALLOW（正常业务）、5 条 BLOCK（应拦）。默认 T=70 无补丁时，误杀 2 个正常大额退款/改单（keyword-overtrigger，误杀率 20%）且漏放 3 个危险动作（2 个注入型 injection-miss + 1 个话术正常的硬案例，漏放率 60%），总代价 340；应用两补丁（把注入案例判官分拉到 90+、把关键词误触发案例拉低）+ 阈值校准到推荐点（本例为 60，比默认更低）后，漏放归零、误杀降到 1 个（10%）、总代价降到 10。所有数字在浏览器端由同一引擎实时算出，不写死结论。

## 10. 明确不做什么
- 不做登录 / 用户系统 / 真实判官或模型接入（不调用任何 LLM）。
- 不接数据库 / 支付 / 外部私钥 / 真实 API。
- 不下达任何真实运行时 block/kill/approve 动作（准星只校准判官、不接管业务）。
- 不做生产级后端。
- 读数引擎是确定性统计替身，不声称是真实模型推断；页面明确标注。

## 11. 成功体验标准
- 用户 3 分钟内能说出：准星解决什么问题（把 LLM 判官接到 kill 前不知道它准不准）、怎么用（导入黄金集→拨阈值看误杀/漏放→打补丁→出厂判定）、增量在哪（相对"评估驱动执行"的 Prefactor，它先**给判官归零**并**敢说"你的判官现在还不能开火"**）。
- 至少一个"后背发凉"瞬间：默认阈值 70 竟然误杀两成正常业务、还漏放 3 个危险动作（含 2 个 prompt 注入攻击）；打补丁 + 校准阈值后漏放归零、误杀减半、代价 340→10 的对比。
- 首屏与出厂判定页明确标注：mock 数据、确定性读数替身、非真实模型推断、准星不下达运行时动作。
