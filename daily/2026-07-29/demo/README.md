# 准星 Zhǔnxīng · 运行时 LLM 判官的「归零校准台」

> 产品机会实验室 · 2026-07-29 Demo（纯前端静态原型，Vite + React + TypeScript）

## 这是什么

当"评估即执行"成为主线（如 **Prefactor** 把 eval 直接接到运行时 hold / approve / block / **kill**），
新瓶颈不再是"能不能拦"，而是：**凭什么相信那个下达拦/杀命令的 LLM 判官是对的？**
报告自己也点破 Prefactor 的命门是"**判官质量**"与"**误杀 / 误批直接打断业务**"。

**准星**坐在"评估即执行"的**上游**，做一件它们都跳过的事——
**在把判官接到运行时开火之前，先用你自己的真实争议案例给它归零**：

- 用一份带**人类专家真值**的黄金集，算出该判官在任意阈值下的**混淆矩阵**
  （命中拦截 / **误杀**（拦下正常业务）/ **漏放**（放过危险动作）/ 正常放行）；
- 画出**代价曲线**："每拦下 1 个坏动作，要误伤多少正常业务"最划算；
- 钻取判官与人类**分歧**的案例、定位**失败模式**（关键词过度触发 / 注入漏判）并打**补丁**验证；
- 给出**出厂判定**：这个判官在哪个阈值能开火、要付多少误伤、还漏不漏危险动作。

一句话：**评估驱动执行，那谁来评估评估者（eval the evaluator）。**

## 它不是什么（不照抄声明）

- 不是又一个"评估驱动的运行时执行平台"（那是 Prefactor 在做）。准星**不下达任何 block / kill / approve**，
  只**校准与验收判官本身**。二者互补：准星甚至可消费判官的历史打分作为输入。
- 不接登录 / 数据库 / 支付 / 外部私钥 / 真实 API / 任何 LLM 调用。

## 怎么用（3 分钟看懂）

1. **① 校准台**：拖动"判官拦截阈值 T"（判官分 ≥ T 即拦）。看混淆矩阵、误杀率、漏放率、代价曲线实时变化。
   默认阈值 70 上线：**漏放 3 个危险动作（含 2 个 prompt 注入）、误杀 20% 正常业务、总代价 340**。
2. **② 分歧**：只看判官≠人类的案例，读它错在哪；打开两个失败模式补丁
   （**去关键词偏置** + **加注入识别**），看判官分被确定性修正、误判被修复。
3. **③ 出厂判定**：并排看"朴素上线 (默认阈值、不校准) vs 准星校准后"的成绩单。
   校准后：**漏放归零、误杀降到 10%、总代价 340 → 10**，并给出诚实结论
   （硬案例建议路由到人工审批 HITL，而非硬调阈值两头受损）。

## 技术说明

- **Vite + React + TypeScript**；`vite.config.ts` 设 `base: './'`（相对路径），
  保证部署到任意 GitHub Pages 子目录都能正确加载资源。
- 全部数据为 **mock**：`src/data/goldenSet.ts`（15 条争议 agent run + 补丁定义）。
- 读数引擎 `src/logic/engine.ts` 为**确定性统计替身**（混淆矩阵 / 误杀率 / 漏放率 /
  代价模型 / 代价曲线 / 推荐阈值），**非真实 LLM 判官推断**；所有数字在浏览器端实时算出，不写死结论。

```
src/
  App.tsx                     顶部导航 + 状态（阈值 / 补丁 / Tab）
  types.ts                    类型定义
  data/goldenSet.ts           mock 黄金集 + 补丁 + 默认阈值
  logic/engine.ts             确定性读数引擎（评估 / 代价曲线 / 推荐阈值）
  components/
    CalibrateView.tsx         校准台：阈值滑杆 + 混淆矩阵 + 成绩单 + 代价曲线
    DisagreementsView.tsx     分歧：失败模式补丁 + 分歧案例卡
    VerdictView.tsx           出厂判定：朴素 vs 校准 before/after
```
