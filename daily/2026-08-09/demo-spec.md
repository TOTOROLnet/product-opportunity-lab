# Demo 设计说明 — 2026-08-09

## 1. Demo 名称

**正名 Zhèngmíng —— 聚合工具面的「意图对号」与影子雷达**（Tool-Surface Disambiguator）

## 2. 一句话定位

坐在 MCP 网关 / lazy-discovery meta-tool 层**之上**、厂商中立、只读的一层：给一片聚合后的工具面 + 一组真实意图，模拟 Agent 会检索/选中哪个工具，把「多义 / 危险近邻 / 盲区」变成可见、可一键正名的一等公民——先把工具的名与述**正**了，Agent 才对得上号。

## 3. 目标用户

把多个 MCP server 聚合进一层（Toolport 类网关 / 自建 meta-tool 层）、并在生产跑 Agent 的平台方与工程团队。

## 4. 使用场景

工具越接越多、越用 lazy discovery、越看不全整份目录时，在 Agent 真正「按需检索→选工具→调用」之前，先跑一遍「意图对号」体检，发现哪些意图会撞车/选到危险近邻/根本检索不到对的工具，并一键消歧。

## 5. Demo 策略分型（重要）

- 本机会属于：☑ 抽象 / CLI / API / 基础设施类产品（MCP 工具层中间件之上的只读审计层）
- 采用的演示方式：纯前端「**模拟体验 + 价值可视化**」——
  - **可搜索/可点选面板**：意图列表 + 每个意图的检索候选与判决（对号台）；
  - **结构 / 雷达视图**：把整片聚合工具面的命名冲突、语义重叠簇、危险近邻、盲区可视化（影子雷达）；
  - **before / after 对比**：朴素 lazy-discovery vs「应用正名」后，同一意图/整片工具面的对号率、危险近邻数、盲区数变化（正名修复）。
- 演示的是**我们分析出的创新切入点**（意图↔工具消歧 + 命名空间正名），**不是** Toolport 的克隆（不聚合、不代理、不省 token、不管密钥）。

## 6. 核心流程（3 分钟内看懂价值）

1. 进入 **对号台**：左侧一组真实 Agent 意图（如「通知值班同事部署完成」「把这条测试记录删掉」「给客户发确认邮件」）。点一个意图，中间显示「lazy-discovery 检索器」召回的 Top-K 候选工具（含匹配分）、高亮 Agent 最可能选中的那个、并给判决徽章：`唯一正确 / 多义 / 危险近邻 / 盲区`，配「为什么」（命名撞车 / 描述遮蔽）。危险案例弹出**翻车预演**卡：例如意图「通知值班同事」→ Agent 选中 `slack.post_channel(#general)`（公开、错），而正确是 `slack.dm`。
2. 切到 **影子雷达**：一张按 server 分组的工具面地图，画出命名冲突、语义重叠簇、贪婪描述、危险近邻（生产 vs 暂存同名）；顶部汇总芯片：`命名冲突 N / 语义重叠簇 M / 危险近邻 K / 盲区意图 P`。
3. 切到 **正名修复**：逐条歧义给一键消歧提案（加命名空间前缀 / 改名 / 收紧描述 / 给破坏性工具加显式确认 + 「暂存库≠生产库」提示）。打开「应用正名」开关，对号台与雷达**实时重算**：多义→唯一、危险近邻→中和、盲区→解决。顶部 before/after 头条：如「对号率 55% → 100%，危险近邻 4 → 0，盲区 2 → 0」。

## 7. 页面结构（<= 3 个主要页面）

- 页面/Tab 1：**对号台**（Intent → Tool bench）——意图列表 + 单意图的检索候选、选中项、判决、翻车预演卡。
- 页面/Tab 2：**影子雷达**（Shadow radar）——聚合工具面结构图 + 冲突/重叠/危险近邻/盲区可视化 + 汇总芯片。
- 页面/Tab 3：**正名修复**（Rectify）——歧义清单 + 一键消歧提案 + 「应用正名」开关 + before/after 统计与逐意图翻转。

## 8. 关键交互

- 顶部全局「**应用正名**」开关：一处切换，三页联动重算（对号台判决翻转、雷达冲突消解、修复页 before/after 数字变化）。
- 对号台点选意图 → 右侧显示检索 Top-K、选中项、判决与理由；危险案例展开「朴素 vs 正名后」两条会被调用的工具对比。
- 雷达上点一个冲突簇 → 跳到修复页对应提案（可选，若时间允许；至少做静态高亮）。
- 所有分数、判决、before/after 统计均由**确定性引擎**算出，非硬编码文案（先用 `_verify.ts` 预验证数字自洽后再接 UI）。

## 9. 使用的 mock 数据（全部 mock，不接真实后端/网关/LLM/密钥）

- `src/data/tools.ts`：一片聚合工具面 ~30–40 个工具，跨 ~8 个 MCP server（github、slack、notion、postgres-prod、postgres-staging、filesystem、email、calendar、jira、stripe 等）。每个工具含：`{ id, server, name, description, tags/关键词, destructive, reversible, env: prod|staging|none }`。刻意植入：同名跨 server（`search`/`delete_record`/`create_issue`）、语义重叠（多个「通知」类）、贪婪描述、危险近邻（prod 与 staging 同操作）。
- `src/data/intents.ts`：~10–12 条真实意图 `{ id, text, family, correctToolId }`。
- `src/data/rectify.ts`：每条歧义的消歧提案 + 应用后对工具的字段覆盖（改名/加前缀/收紧标签/加确认）。
- 说明：这是**确定性关键词/标签打分**模拟的 lazy-discovery 检索器，用于演示与价值可视化；真实产品需贴合各网关的 embedding/排序策略并接入真实调用轨迹，Demo 如实标注为**模拟**。

## 10. 明确不做什么

- 不做登录 / 用户系统。
- 不接数据库 / 支付 / 外部私钥 / 真实 API / 真实 MCP 网关 / 真实 LLM embedding。
- 不做生产级后端；不真正代理或调用任何工具（对号台的「调用」全是模拟展示）。
- 不复刻 Toolport 的聚合/省 token/密钥管理能力。

## 11. 成功体验标准

- 用户 3 分钟内能说出：它解决什么（聚合 + lazy discovery 后 Agent 会选错/漏选工具）、怎么用（意图对号 → 看判决 → 一键正名）、增量在哪（网关只管「多而省」，正名管「准而不撞」，且指纹只查篡改、查不到诚实工具间的遮蔽）。
- before/after 能直观看到「对号率上升、危险近邻与盲区归零」。
- 首屏不空白，核心交互路径闭合，全 mock 可离线跑。
